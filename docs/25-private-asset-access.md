# REQ-ASSET-PRIVATE 画布资源私有访问：判权后跳转签名 URL

> 状态：**规划中**（只记录方案，暂不实施）。现状见 [REQ-CANVAS §3.7「资源上传」](13-flow-canvas-management.md)。

## 1. 背景

画布上图片 / 视频节点的资源存在 S3（集群内 MinIO，经 `s3.fyl080801.uk` 对外）。现在的做法是：

- 上传经后端转存，节点的 `data.src` 里记的是 **S3 原始地址**（`<S3_ENDPOINT>/<bucket>/<key>`），浏览器直接读；
- 所以桶必须**对匿名开放读**（`s3:GetObject`）。

问题：

- **知道地址的任何人都能读**，与画布 / 项目的成员权限无关。画布被移出项目、成员被移除之后，拿着旧地址照样能读；
- ~~线上的桶对匿名开放了列举和写入~~ **已收紧（2026-10-30）**：桶 `temp` 原来的匿名策略是 `readwrite`（匿名可列出、读、上传、覆盖、删除）；现已改为**匿名只有 `s3:GetObject`**，实测匿名列出 / 上传 / 删除均 `AccessDenied`，读对象照常 200。服务端上传用带签名的凭据，不受影响。

## 2. 目标

- 桶改为**私有**：不再有任何匿名读 / 列举；只有服务端的凭据能读写。
- 浏览器读资源前**按当前用户的权限判断**：能访问这张画布所在项目的人才能读。
- 资源的大流量（图片、视频、拖动进度条）**不经过服务端**，仍由 MinIO 直接下发。
- 节点里存的地址**长期有效**，不随签名过期而失效（`data.src` 在 Y.Doc 里，所有协作者共享、长期保存）。

## 3. 方案（B：判权后 302 到短期签名 URL）

### 3.1 资源地址

- 节点 `data.src`（以及视频的 `poster` 等资源字段）改存**应用内的稳定地址**：`/api/assets/<key>`（相对路径，同源，和所有 `/api/*` 一样）。
- 浏览器 `<img>` / `<video>` 请求它时自动带上登录 cookie，不需要前端额外处理。

### 3.2 读取流程

1. `GET /api/assets/<key>`：服务端解析对象键 → 查这份资源归属的项目 → 当前用户是该项目成员才继续，否则按现有约定回 **404**（非成员一律 404，不暴露资源是否存在）。
2. 通过后服务端用 SigV4 **预签名一个 GET URL**（指向公开的 `S3_ENDPOINT`，浏览器要能访问；有效期建议 5 分钟），回 **302** 跳过去。
3. 浏览器直接从 MinIO 拿字节；视频的 `Range` 请求由 MinIO 原生处理。
4. 302 响应 `Cache-Control: private, max-age` 不超过签名有效期（建议直接 `no-store` 或略短于有效期），避免跳到已过期的签名。

签名在现有的手写 SigV4 客户端（`apps/server/storage/s3.ts`）上加一个预签名方法即可，**不引新依赖**。

### 3.3 资源归属

- 对象键现在是统一的 `assets/<uuid 两级目录>/…`，**从键上看不出属于哪个项目**，所以需要在上传时记录归属：新增一张资源表（对象键、所属项目、上传人、类型、大小、创建时间）。
  - 现状：上传记录表 `FlowAsset` 已经有了（对象键、所属**画布**、服务端看到的类型、上传人、创建时间；[REQ-CANVAS 4.7](13-flow-canvas-management.md)「上传记录」），先用于 agent 消息附件的归属核对。所属项目可经画布得出；实施本方案时再定要不要补项目、大小两列，以及画布真删时记录是否随之级联（现在是级联）。
- 判权 = 「当前用户是该资源所属项目的成员」（个人空间即所有者本人）。
- agent 看图（`view_node_media`）本来就是把地址反解成对象键、再经服务端用服务端凭据读取，不经浏览器，不受影响；判权沿用 agent 自己这一轮的授权（Grant）。

### 3.4 旧数据兼容

- 已存的节点里还是 S3 原始地址。前端渲染时把以 `<S3_ENDPOINT>/<bucket>/` 开头的地址**映射成** `/api/assets/<key>`（反解逻辑已在 `apps/server/storage/keys.ts`，可挪到 `packages/shared` 复用）；或者一次性迁移脚本改写所有画布的 Y.Doc。二选一，实施时定。
- 线上 2026-10-30 已换成空库，当下没有存量；从 Prisma 旧库（`app.db.prisma-backup-20261030`）导入数据时要一并处理。

### 3.4.1 缩略图

缩略图（[REQ-ASSET-THUMB](27-asset-thumbnails.md)）用查询参数取档：`/api/assets/<key>?size=icon|low`，判权按原图的键，302 到那一档的签名 URL；档位对象键规则不变。

### 3.5 存储侧

- MinIO 桶策略：去掉匿名的 `s3:GetObject` 和 `s3:ListBucket`；服务端账号保留读写。
- 只用 `<img>` / `<video>` 显示时不需要 CORS；以后若要把图片画进 `<canvas>` 或用 JS 读字节，再给应用域名配 MinIO 的 CORS。

### 3.6 项目画布多人共享

判权的单位是**项目成员**，不是上传人，所以共享是方案的默认形态：

- **Y.Doc 里的地址与用户无关**：所有协作者拿到同一个 `/api/assets/<key>`，各自的浏览器带各自的 cookie 去判权、各拿一个签名 URL。**签名 URL 永远不写进 Y.Doc**（会随文档泄给所有人，而且会过期）。
- **资源归属于项目**：A 上传的图，同项目的 B、C 都能读；A 被移出项目后图仍属于项目，其他人照常读。资源表里的上传人只做审计。
- **成员变化**：新成员经分享链接加入后立即可读该项目全部资源（没有匿名入口，不存在非成员看画布）；被移除的成员下一次请求即 404，与协同撤权（WebSocket 断开，[REQ-COLLAB](04-realtime-collab.md)）一致。残留：已签出的 URL 在有效期内仍可用；浏览器已缓存的字节不会被收回（对象可设 `Cache-Control: private` 并缩短 `max-age`）。
- **先落库、再写 `src`**：A 上传完，B 几乎同时就会在画布上看到节点并请求资源，所以资源归属记录必须在 `src` 写进 Y.Doc **之前**落库 —— 上传接口返回前写好（分片上传在 complete 时写），前端拿到返回值才写节点。
- **人多图多**：每个协作者 × 每张图各一次判权 + 302。服务端可短时缓存「用户 × 项目」的成员判断（如 30 秒，代价是撤权最多晚这么久生效），302 也可在签名有效期内让浏览器复用。
- 个人画布：只有所有者本人可读。agent 看图走服务端，按这一轮的委托授权（Grant）判权，与成员判权同一规则。

## 4. 取舍与已知限制

- **签名 URL 在有效期内可被转发**：拿到 302 目标地址的人在几分钟内能读到这一个对象。比现在「永久可读」收紧很多，但不是绝对的；需要更严时改用方案 A（见 §6）。
- **多一次往返**：每次加载资源先打一次服务端再跳转。图片多的画布首屏会多一批 302 请求；可以在前端合并或适当缓存。
- **判权要查库**：每次请求查一次资源表 + 成员关系，需要索引；后续可加短时缓存（注意成员被移除后的生效延迟）。

## 5. 待确认事项

1. **跨项目复制节点**（把一张画布里的图片节点粘贴到另一个项目）怎么判权：
   - 粘贴时**复制一份对象**，归属新项目（规则简单，多占存储）；或
   - 判权改为「用户能访问**任何一张引用了它的画布**」（省存储，判权更重）。
2. 旧地址兼容用**前端映射**还是**一次性迁移**。
3. 签名有效期取多少；302 的缓存策略。
4. 资源被所有画布都不再引用时是否清理对象（与本方案独立，可另立需求）。
