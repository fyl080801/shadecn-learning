# CLAUDE.md

## Language

**Always reply in Chinese (中文).** All user-facing output — answers, explanations, plans, summaries, questions — is written in Chinese. Keep technical terms in their original English form (Vite, MikroORM, OIDC, Hono, …).

Code identifiers, types and commit messages stay English. **Source comments in `apps/server/`, `apps/agent-sandbox/`, `apps/web/src/`, `packages/` and `scripts/`, log/error messages shown to a developer or user, and test names are written in Chinese**, matching every existing file. `docs/` is Chinese too.

## Project

A Vue 3 learning sandbox: shadcn-vue UI, Three.js scenes, canvas mini-games, and one real feature — collaborative flow canvases (projects, Yjs, an agent). Requirements live in `docs/`, one file per requirement (index: `docs/README.md`); `docs/` says *what*, this file and `.claude/rules/` say *how*.

### Where a fact goes — `docs/` vs `.claude/rules/`

- **`docs/`** — product behaviour: features, interactions, what is on screen and where, which types / options exist, acceptance criteria, what is deferred. **A requirement change updates `docs/` only.**
- **`.claude/rules/`** — only constraints a reader of the code would get wrong by following intuition: the one write path, forbidden shortcuts, cross-module invariants, cycle rules, and *why* each holds. Don't restate behaviour; point at it (`docs/13` §3.7).
- **Test:** if a line would only change because a requirement changed, it belongs in `docs/`, not in a rule. Don't add component inventories, UI layouts, type lists or "not wired yet" notes to a rule.

## Monorepo layout

pnpm workspace. Every root command is a `pnpm --filter <pkg>` delegation.

- **`apps/web` (`@shadecn/web`)** — frontend (`src/` = `@/`, `vite.config.ts`, `index.html`, `login.html`, `components.json`). `devDependencies` only: it is bundled into `output/public`.
- **`apps/server` (`@shadecn/server`)** — assembles the backend product: entries `index.ts` / `dev.ts`, the module list `modules.ts`, the `db:push` entry `db-sync.ts`, `scripts/`, and the integration tests. Its `dependencies` is the production runtime set.
- **`apps/agent-sandbox` (`@shadecn/agent-sandbox`)** — the agent's `oci` sandbox image: its own esbuild of the runner (which it checks against the runner boundary), the image's `Dockerfile` and `build-image.mjs`. Its `dependencies` is the runner's runtime set. The runner's source stays in `packages/agent` (`.claude/rules/agent.md`).
- **`apps/platform` (`@learning/platform`)** — a standalone NestJS service on `@nestjs/platform-fastify`, default port 3001. It hosts `apps/web` through `@learning/web`: `NODE_ENV=production` serves `output/public`, anything else mounts Vite (`pnpm dev:platform`; `pnpm build:platform` + `pnpm start:platform`). Backend routes must stay under `/api`. `src/app.module.ts` lists only static modules and holds no configuration: each module reads its own section of `<dataDir>/config.yaml` through `@learning/config` (sample: `apps/platform/config.example.yaml`), secrets come from the `.env` in the working directory (`apps/platform/.env` under `pnpm dev:platform`; sample: `apps/platform/.env.example`), and `main.ts` only calls `@learning/foundation`'s `bootstrapService`. Its database comes from `@learning/data-access`, its users and sessions from `@learning/session`, and `src/page-auth.module.ts` binds `SessionPageAuth` to `@learning/web`'s `WEB_PAGE_AUTH`. Every page and `/api` route requires a session, in dev too (`.claude/rules/auth.md`); login is OIDC and GitHub through `@learning/session` (`auth` and `server.origins` in `config.yaml`, secrets in `apps/platform/.env`, `docs/02` §3.3.2). It has no controllers or business API of its own yet and is not part of `pnpm build` or the app image. **It and the `@learning/*` packages don't depend on `@shadecn/*`** (pinned by a boundary test in each): `nest build` is plain tsc, so a source-only package would break once it sits under `node_modules` in an artifact (`ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`). The one remaining link is the frontend: `pnpm build:platform` builds `@shadecn/web` first. Its `tsconfig` leaves out `erasableSyntaxOnly` (decorators and constructor parameter properties need it off); its vitest project transpiles through swc, because the root vite's esbuild drops `emitDecoratorMetadata`.
- **`packages/config` (`@learning/config`)** — the global Nest module `ConfigModule` + `ConfigService`: reads `<dataDir>/config.yaml` and `<cwd>/.env` during startup (`dataDir` = env `DATA_DIR`, else `<rootDir>/data`; `rootDir` = the nearest `pnpm-workspace.yaml` above `process.cwd()`, else cwd). A missing file is an empty config; bad YAML or a non-mapping top level refuses to start, and the error carries the path, never the content (`yaml`'s default messages are off). `.env` only feeds `ConfigService.env(name)`: process env wins, it is never written back to `process.env` (secrets don't reach Vite or child processes), and `NODE_ENV` / `DATA_DIR` ignore it (from the repo root, cwd's `.env` is `@shadecn/server`'s). It validates no section: **each section's validation and defaults belong to the module that reads it.** Business modules inject the global `ConfigService` without importing `ConfigModule`, and tests swap it through `@learning/config/testing`'s `testConfigModule(values, options)` (not exported from the main entry). **The class is the DI token, so a process must hold one copy**: business packages declare it as a peer (`packages/data-access/test/dist.test.ts` runs the real output against it). Vitest aliases must list `@learning/config/testing` before `@learning/config`. Compiled with tsc like `@learning/web`.
- **`packages/web` (`@learning/web`)** — the static Nest module `WebModule`: hosts a frontend as Vite middleware (`dev`) or built static files (`static`), Fastify only. Its section is `web`; `mode` follows `isProduction` and can't be configured. The page gate is on unless `web.auth: false`; something must then provide `WEB_PAGE_AUTH` (`.claude/rules/web-shell.md`). Unlike `@shadecn/*` it is **not source-only**: decorators can't be type-stripped, so it compiles to `dist/` and consumers run that (`apps/platform`'s `build` / `dev` build it first; its `dev` watch does not pick up changes here at runtime — rebuild and restart). The `source` export condition (`customConditions` in the consumer's `tsconfig`) and a vitest alias let typecheck and tests use the source without a build. `vite` is an optional peer: only `vite-host.ts` loads it, through a dynamic `import()`; a static one would break production.
- **`packages/foundation` (`@learning/foundation`)** — the service bootstrap: `bootstrapService(AppModule, { name })` = FastifyAdapter, `enableShutdownHooks`, `/api/health`, listen on `server.port` and `server.host` (`serverPort`, `serverHost`, validated here; no host = localhost only, a container writes `0.0.0.0`), startup log. **`/api/health` is a plain Fastify route, not a Nest controller**: `ApiSessionGuard` guards every Nest route under `/api`, and this package can't use `@learning/session`'s `@Public()` (neither depends on the other). A controller declaring the same path fails the start (Fastify's duplicate route). Compiled with tsc like `@learning/web`, built first by `apps/platform`.
- **`packages/cluster` (`@learning/cluster`)** — the static global Nest module `ClusterModule`: injects `Cluster` (`createLock(namespace)` → `SharedLock`; `mode`). Its section is `cluster` (`mode`, `url`; the password form goes in `.env`'s `PLATFORM_REDIS_URL`). Only the lock exists so far; the other shared structures come with collab. `ioredis` loads through a dynamic import, so `single` never touches it. It knows no business module: `assertClusterDatabase` takes the database type as an argument and `apps/platform` wires it (`.claude/rules/cluster.md`). Consumers declare it as a peer: `Cluster` is a DI token. Compiled with tsc like `@learning/web`, built first by `apps/platform`.
- **`packages/data-access` (`@learning/data-access`)** — the static global Nest module `DataAccessModule`: syncs the schema during startup and injects `DataAccess` (`em()`, `transactional(fn)`, `orm`). Its section is `database` (`url`, `schemaSync`). It owns `User`, the column helpers, `openOrm` and the schema-sync guard; **every other entity is registered by the module that owns it** through `{ provide: DATA_ACCESS_ENTITIES, useValue: [...] }` (`.claude/rules/database.md`), so a process without a module has no tables for it. Compiled with tsc like `@learning/web`, built first by `apps/platform`. It declares the DB drivers itself, because the dynamic imports resolve from its own `node_modules`; `@learning/config` and `@nestjs/*` are peers (their classes are DI tokens). Consumers declare this package as a peer too: its `User` and `DATA_ACCESS_ENTITIES` must be one copy.
- **`packages/session` (`@learning/session`)** — users, sessions and login, in two static modules: **`SessionIdentityModule`** (global; `session` section + `auth.oidc`; needs `ClusterModule` in the root): `UserService`, `SessionService` (read, renew under the shared lock), `SessionGuard`, `ApiSessionGuard` + `@Public()`, `SessionPageAuth`, `@CurrentUser()`; **`LoginModule`** (`auth` section + `server.origins`): the OIDC / GitHub login flow, `/api/auth/{me,config,login,callback,login-done,logout}`, the hourly sweep. `SessionModule` imports both. It owns the login protocol code (`src/oauth/`), `resolveLoginIdentity` and the auth tables (`src/entities.ts`). Account linking isn't implemented: `PendingLink` is a definition only (`.claude/rules/auth.md`). Compiled with tsc like `@learning/web`. **It imports no `@shadecn/*`, and from `@mikro-orm/*` only `core`** (`test/package.test.ts`); `@learning/data-access`, `@learning/config`, `@learning/cluster` and `@mikro-orm/core` are peers, so a process has one copy of each. `@learning/session/testing` is a fake IdP over real HTTP plus a cookie-keeping fake browser, for tests and smoke runs.
- **`packages/shared` (`@shadecn/shared`)** — source-only TS both sides import: `flow-graph`, `flow-node-types`, `flow-doc`, `flow-ops`, `canvas`, `auth`, `collab`, `agent`, `id`, `apps`. Change a contract here, once.
- **`packages/agent` (`@shadecn/agent`)** — the canvas agent, source-only, never in the browser: server-side orchestration + gateway, and the sandboxed runner each run spawns (bundled twice: `output/server/agent-runner.js` for the `process` driver, `output/agent-sandbox/` for the image; `.claude/rules/agent.md`).
- **`packages/server-kit` (`@shadecn/server-kit`)** — the server's runtime library, source-only: the module integration protocol + kernel, the platform contract (`platform`, `db`, `identity`), ORM construction, schema sync, session token functions and the login protocols with no config behind them (`orm`, `schema-sync`, `session`, `oauth`), config layer, shared layer (`cluster`), bus, access-revocation signal. **`packages/server-core` (`@shadecn/server-core`)** — the core (HTTP pipeline, config, DB, logging, frontend hosting, platform implementation, `prepare` / `assemble` / `boot`); it knows no module. **`packages/mod-*`** — one package per capability (`mod-auth` — login, provides the platform's `auth` —, `mod-canvas`, `mod-storage`, `mod-collab`, `mod-agent`, `mod-apps` — `executeApp` over pluggable drivers, `docs/29` —), each default-exporting a module declaration (config section, tables, routes, `setup`). Core and modules never import each other; they meet only in `apps/server`'s entries (`.claude/rules/server-modules.md`, `docs/28` §3.1).
- **Root**: `docs/`, `k8s/`, `ci/`, `.gitea/`, `scripts/` (`build-all.mjs` behind `pnpm build`, `bundle-common.mjs` shared by the two esbuild builds), `Dockerfile`, `.env`, `data/`, `output/`, `eslint.config.ts`, a `vitest.config.ts` that only aggregates `projects`, and repo-wide tooling devDependencies.
- **Two base directories.** `rootDir` / `appRoot` (`@shadecn/server-core`'s `config.ts`, `runtime.ts`) is the **repo root** — home of `.env`, `data/`, `output/`. `webRoot` and `serverDir` are each package's own dir. From source, `runtime.ts` derives the app root as **three levels above `packages/server-core/src/`**; in the bundle it is `process.cwd()`. Mixing them reads the wrong `.env` or puts the DB in the wrong `data/`.

### Invariants — each is a bug if undone

- **`tsx watch` carries `--exclude '../web/node_modules/.vite-temp/**'`** in `dev` and `dev-cluster`. Vite's temp config file sits outside tsx's default ignore and causes an endless restart loop.
- **The schema-sync CLI (`apps/server/db-sync.ts` → `@shadecn/server-core/db-sync`) loads env through the core's `env.ts` + `config.ts`**, never its own `.env` read (cwd is `apps/server`, so a bare `loadEnvFile()` finds nothing and silently uses the default SQLite file); it takes the module list so it syncs every module's tables.
- **Local `pnpm start` goes through `node --import ./apps/server/scripts/local-start.mjs`.** Runtime deps are declared only in `apps/server`, so the hook re-resolves "bare package not found" from `apps/server/package.json`. In a container the artifact has its own `node_modules`.
- **Root `Dockerfile`: copy each package's `package.json` one by one → `pnpm install --frozen-lockfile` → `COPY . .`** (cacheable install layer; a new workspace package needs one more `COPY` line). `.dockerignore` says `**/node_modules` — a leaked symlink dir would overwrite installed deps.
- **Tailwind's source scan is rooted at `apps/web`**; class names outside it are not detected.
- **esbuild uses the `externalizePackages` plugin, not `packages: 'external'`**: bare imports stay external except `@shadecn/*`, which is inlined (it's installed nowhere in the artifact). Shared's own third-party imports (yjs, `@dagrejs/dagre`) stay external and enter the runtime dependency list.
- **`@shadecn/shared` is a `workspace:*` devDependency of web and server, and peer-depends on `yjs` and `@dagrejs/dagre`** (the layout in `flow-layout` runs in the browser and, for the agent's `auto_layout`, on the server — so the server lists dagre in `dependencies`). Exactly one yjs copy per bundle, or `instanceof Y.Map` is always `false` and canvases go blank. Guaranteed by pnpm linking + the frontend's `resolve.dedupe`; pinned by `apps/server/test/collab/shared-yjs.test.ts` and `apps/web/src/test/lib/sharedYjs.test.ts`.
- **Writing `packages/shared`**: relative imports carry `.ts`; no DOM or Node API (`lib: ["ES2020"]`, `types: []` — both consumers recompile it under their own config). Tests use `tsconfig.test.json` so vitest's Node types don't switch the guard-rail off.
- **Lockfile ranges were kept identical to the pre-monorepo ones** (a fresh resolve drifts `reka-ui` to 2.10.1). Don't `pnpm update` casually; read the lockfile diff of any install.

## Commands

- `pnpm dev` — whole app (Hono + Vite middleware, watch) on http://127.0.0.1:3000. One process, one port, no proxy, in dev and prod.
- `pnpm build` — `build:client` (`vue-tsc -b` + `vite build` → `output/public`), `build:server` (`typecheck` + esbuild → `output/server`), `build:sandbox`, all with one `AGENT_BUILD_ID`.
- `pnpm build:sandbox` — `typecheck:agent` + typecheck + esbuild of the runner → the agent sandbox image context `output/agent-sandbox/`; fails if the runner's closure crosses the boundary. Touches nothing else in `output/`.
- `pnpm build:sandbox-image` — `build:sandbox`, then build the agent's oci sandbox image with podman / docker; extra args go to the build (`--build-arg NODE_IMAGE=…`). Rebuild it whenever the runner or the gateway protocol changes.
- `pnpm start` — run `output/` locally; `pnpm preview` = build + start.
- `pnpm typecheck:server` / `typecheck:shared` / `typecheck:agent` / `typecheck:agent-sandbox` (frontend is checked by `vue-tsc -b` in `build:client`).
- `pnpm test` (`test:watch`, `test:coverage`) and `pnpm test:server` / `test:client` / `test:shared` / `test:agent` / `test:agent-sandbox`.
- `pnpm lint` / `pnpm lint:fix`.
- `pnpm db:push` — sync tables to entities; additive only, lossy changes are refused with the statements printed. `pnpm dev` runs it first. **No migration files.** No `db:studio` — use `sqlite3` / `psql`.
- `pnpm db:push:force` — same with `--force`; **dev only, deliberately separate** (`dev`, `dev:cluster` and both Dockerfiles keep the bare sync).

Copy `.env.example` → `.env` (repo root) before the first run.

## Architecture

**Stack:** Vue 3 + TypeScript + Vite + Tailwind CSS v4 + shadcn-vue (new-york). `@/` → `apps/web/src/`; shared code is imported as `@shadecn/shared/<subpath>`, never through `@/`. Frontend, `/api/*` and `/ws/collaboration` are same-origin in every mode — use relative paths.

Details live in `.claude/rules/`, one file per area, each loaded when you touch a path it lists. **Read the matching file before changing code in that area** — each is a set of invariants where the obvious change is a known bug:

- **Canvas editor** — `flow-editor.md`: views and workspace, editor context, node-type registry and node-kit, selection / groups / snapping, the store as a *projection of a Y.Doc* (`store.mutate()` is the only write path), five-group node schema, collection keys, drafts, viewport state, personal canvases.
- **Collaboration** — `collab.md`: data vs feedback layer, Hocuspocus mount and timings, persistence (read → merge → CAS; **a failed store must propagate**), quota, awareness, one-window-per-user, terminal close codes, revocation, write gate, WebSocket `Origin`.
- **Frontend shell** — `web-shell.md`: router + layouts, frontend auth and popup re-login, shadcn-vue (`Button.vue` is hand-edited), `@lucide/vue` only, theme gotchas, views.
- **Backend runtime** — `server-runtime.md`: `packages/server-core` + `apps/server` file map, logging (keep writing `console.*` with a `[prefix]`), frontend hosting and the login entry, the build.
- **Auth** — `auth.md`: OIDC + GitHub BFF, provider registry, per-request callback origin, sessions, confirmed account linking, identity is `(provider, subject)` never email, profile hooks, avatars.
- **Database** — `database.md`: entities, SQLite *or* PostgreSQL, entity rules, Prisma habits that are now bugs, schema-sync guard, `containsIgnoreCase()`.
- **Clustering** — `cluster.md` · **Deploy** — `deploy.md` · **Tests** — `testing.md` · **Agent** — `agent.md` · **Apps** — `apps.md`.

When a fact goes stale, fix it where it lives — each fact has one home. If a stale fact sits in a rule but is really a requirement, move it to `docs/` instead of rewriting it in place.

## Dependencies

Each package declares only what it needs; **the runtime set is `apps/server/package.json`'s `dependencies`** (and `apps/agent-sandbox/package.json`'s for the sandbox image), everything else is `devDependencies`.

- A package the **server** imports → `apps/server` `dependencies` (`pnpm --filter @shadecn/server add -P`). `build-server.mjs` fails the build if the bundle imports something only in `devDependencies` or missing.
- A **frontend** package → `apps/web` `devDependencies` (`pnpm --filter @shadecn/web add -D`; the shadcn-vue CLI, run from `apps/web`, writes there).
- Never hoist to the root unless it's repo-wide tooling (eslint, typescript, vitest + coverage, jsdom). The root also holds `pnpm.neverBuiltDependencies: ["better-sqlite3"]` (see `deploy.md`).
- `@mikro-orm/*` is pinned to exactly `7.2.5`; both DB drivers and both cluster packages (`ioredis`, `@hocuspocus/extension-redis`) stay in every artifact — DB and mode are runtime choices.

## Conventions

- TypeScript strict with `noUnusedLocals`, `noUnusedParameters`, `erasableSyntaxOnly`. All Vue components use `<script setup lang="ts">`.
- Tests live in `apps/server/test/`, `apps/agent-sandbox/test/`, `apps/web/src/test/`, `packages/*/test/`, mirroring what they cover. Imports in `apps/server/` (tests included) keep explicit `.ts` extensions. Import `describe` / `it` / `expect` / `vi` from `vitest` (no globals). Name tests by the behaviour constrained ("未登录 → 401").
- **Time is UTC everywhere except on screen.** The DB stores absolute instants; stores map rows out with `toISOString()`, so the wire format is always ISO with `Z`. **The frontend never formats a date inline** — use `apps/web/src/lib/format.ts` (`formatDateTime` / `formatDate` / `formatTime` / `formatWith(value, options)`; all render `-` for unparseable input).
  - The defaults come from `apps/web/src/lib/preferences.ts` (browser-local `app:display-preferences`; each field defaults to `AUTO` = follow the browser). `format.ts` reads the reactive `resolvedDisplayPreferences`, so changes re-render live. A **caller-supplied option always wins**, and stored values are **validated on read** (a bad `dateStyle` makes `Intl` throw).
- **On the canvas path, time is a number** — UTC epoch ms (`FlowNodeData.createdAt`, `FlowEdgeData.createdAt`). Stamped by each browser's own clock, so never order across clients by it.
- **One click, one request — every write-side interaction goes through `apps/web/src/composables/useAsyncAction.ts`.** `const { run, pending } = useAsyncAction(fn, { errorMessage })`; `run()` marks pending **synchronously**, so a same-tick second click is dropped (`:disabled` lands a render too late, and Enter / `@select` / blur / `AlertDialogAction` have no button). Bind `<Button :loading="pending">`. `run` never rejects and toasts errors (`onError` overrides), so action bodies carry no `try/catch`. Lists pass `key: (item) => item.id`. **Write `@click="submit()"`, not `@click="submit"`** (the latter passes the MouseEvent). Reads are out of scope.
- **Client-generated ids go through `apps/web/src/lib/id.ts`'s `createId(prefix)`** (`<prefix>_<base36 time>_<random>`); the random tail keeps two clients from minting the same id in one millisecond.
