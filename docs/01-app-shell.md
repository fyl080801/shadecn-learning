# REQ-SHELL 应用外壳：布局、导航、路由

## 1. 目标

给所有验证页面提供一致的容器：一套侧栏导航、一套路由规则、一套登录态展示。页面作者只需要写页面本身，不必关心导航、鉴权跳转和布局。

## 2. 功能需求

### 2.1 整体布局

- 应用占满视口高度（`h-screen`）。
- **布局是模板页，不是外壳里的条件分支。** `src/layouts/` 下一个布局一个组件，路由表里作为父级路由挂载，页面渲染在布局自己的 `<RouterView>` 上；`App.vue` 只剩一个 `<RouterView />` 和全局 `Toaster`。
  - `SidebarLayout` —— 左侧固定侧栏 + 右侧内容区，绝大多数页面用它。
  - `BlankLayout` —— 整屏，无侧栏，给需要独占屏幕的页面用（目前只有画布编辑器 `/flows/:id`，见 [REQ-CANVAS](13-flow-canvas-management.md)）。
- 无侧栏**不是登录态的例外**：登录页由服务端模板渲染（见 [REQ-AUTH](02-auth-keycloak.md) 3.1.1），根本不进 SPA；`BlankLayout` 下的路由同样是登录后才进得来。
- 右侧内容区自己管理滚动，`body` 不应出现滚动条。

### 2.2 侧栏导航

- 侧栏顶部是品牌区（Logo + 应用名 + 版本徽标），点击回首页。
- 中部是导航列表，每项包含图标 + 名称，当前路由对应项高亮。
- 底部是用户菜单（见 2.3）；折叠开关在顶部品牌区那一行。
- **桌面端**（宽度 > 768px）：
  - 可折叠。展开宽度 240px，折叠宽度 64px，宽度变化有过渡动画。
  - 折叠态只显示图标，隐藏文字与用户信息文本。
- **窄屏**（≤ 768px）：
  - 默认收起，侧栏移出视口外；左上角显示一个悬浮菜单按钮用于唤出。
  - 展开时覆盖内容区并显示半透明遮罩，点击遮罩或点击任一导航项后自动收起。

### 2.3 用户菜单

侧栏底部是**一个下拉菜单**，不是一排按钮：账号相关和低频入口都收在这里，导航列表只留页面。

- 触发区常驻（不受 `authEnabled` 影响）：头像（无头像时用占位图标）+ 显示名 + 邮箱 + 展开箭头；折叠态只剩头像，名字挪到 `title` 上。
  - 名字的口径：已登录显示用户名；启用了鉴权但没登录显示「未登录」；后端没配 Keycloak 显示「本地模式」—— 那是开发模式，不是会话没了，不能说成「未登录」。
- 菜单项：**设置**（`/settings`）、**关于**（模态窗），再往下才是账号操作。
  - 仅当 `authEnabled` 时才有账号那一组：已登录是「退出登录」（destructive 样式，带当前 `fullPath` 回跳），未登录是「登录」。
  - **「退出登录」要先确认**（`AlertDialog`，取消 / 退出），确认之后才整页跳去 `/api/auth/logout`。退出是不可撤销的整页跳转，点错了得重新走一遍 Keycloak，而这一项就挨着「设置」「关于」——误点的代价和距离不成比例。
- 「关于」不在中部导航列表里 —— 它属于「关于这个应用」而不是一个功能页。
- **「关于」是模态窗，不是页面**（`src/components/AboutDialog.vue`，没有路由）：它只是一段项目介绍，没必要占一条路由，也没必要把人从当前页面带走 —— 看完关掉，原来那页还在。
- 手机端点菜单项后抽屉照常收起（靠 `route.fullPath` 的 watch，与点导航项是同一条路径）。

### 2.4 路由

- 使用 vue-router 5，history 模式（无 hash）。
- 路由表在 `src/router/index.ts` 中声明，一个视图 = 一条路由；顶层只有两条记录，就是 2.1 的两张模板页，页面都作为它们的 `children` 平铺在下面。
- 路由表里**只有需要登录的页面**：`/login` 不是 SPA 路由，未登录的浏览器根本拿不到这份 bundle，所以不需要 `meta.public` 这类字段；页面套哪张模板页由它挂在哪条父级路由下决定，也不需要 `meta.layout` 这类字段。
- 体量大的页面（编辑器、导演台、流程图等）必须用动态 `import()` 懒加载；轻量页面可以静态导入。

#### 2.4.1 标签页标题

- 统一格式：**`区域` 或 `区域 - 具体名`**，例如「画布项目」「画布 - 下单主流程」。
- 每条路由在 `meta.title` 里声明区域名，`router.afterEach` 负责写进 `document.title`；挂在 `afterEach` 而不是 `beforeEach`，是为了让被守卫拦下的导航不改标题。
- 名字要等数据加载才知道的页面（项目主页、画布编辑器、邀请页）再用 `usePageTitle(区域, () => 名字)` 覆盖成两段式 —— 数据没到时先只显示区域名，到了自动补上，改名也会实时跟着变。

#### 2.4.2 视图目录

**路由表平铺，视图文件按功能分目录** —— `src/router/index.ts` 是唯一 import `src/views/` 的地方，所以挪动视图只会牵动这一个文件。

| 目录 | 装什么 |
|---|---|
| `views/` 根 | `Home.vue` / `Settings.vue` —— 不属于任何功能的外壳页 |
| `views/canvas/` | [REQ-CANVAS](13-flow-canvas-management.md)：`Projects` / `ProjectHome` / `InviteAccept` / `FlowEditor` |
| `views/three/` | 3D 相关：`ThreeEditor`（[REQ-3DEDITOR](06-three-editor.md)）、`3DScene`（[REQ-DIRECTOR](07-director-console.md)）、`Canvas3D` / `LightScene` 占位页、`Emu3DView` |
| `views/games/` | 小游戏：`Demo3` / `SnakeGame` / `Game2048` |
| `views/demos/` | 单页能力验证：`FlowChart`（[REQ-FLOW](09-flow-chart.md)）、`RichEditor`（[REQ-PROMPT](08-prompt-input.md)）、`HiC`、`Example` |

新增页面先想清楚归哪一格；哪一格都不像，说明它可能该是个独立需求。

### 2.5 登录守卫

登录与否的**判定在服务端**（Node 中间件，见 [REQ-AUTH](02-auth-keycloak.md) 3.1.1）。前端守卫只是兜底，处理「用着用着会话过期」：

1. 调用 `fetchSession()` 拿登录态（内部缓存，整个会话只请求一次 `/api/auth/me`）。
2. 后端未启用鉴权，或已登录 → 放行。
3. 否则 `location.replace('/login?redirect=<目标 fullPath>')` 并中断这次导航 —— 登录页是服务端渲染的整页，SPA 内部跳不过去。

### 2.7 设置页与显示偏好

`/settings` 一页三块，入口只有侧栏底部的用户菜单。

**用户信息**（只读）：头像、显示名、邮箱和用户 ID 一行，下面是显示名、用户名、邮箱。用户 ID 只是个标识符，跟在头像那一行的右侧；OIDC subject 和角色不展示（页面上没人用得着）。全部来自 `/api/auth/me` —— 前端手上没有 token，这里能看到的就是全部；要改得去账号中心（Keycloak）。后端没启用鉴权时这一块给一句说明，不假装有用户。

**外观**：深色 / 浅色 / 跟随系统三档，`src/lib/theme.ts`。

- 配色本身一直是齐的 —— `src/styles/tailwind.css` 里 `:root` 和 `.dark` 两套变量、`@custom-variant dark (&:is(.dark *))` 都是 shadcn 带来的，缺的只是**没人往 `<html>` 上加那个 `.dark` 类**。所以这个功能落到实处就是「谁来加这个类」：`useColorMode`（@vueuse/core）负责读写偏好、监听系统的 `prefers-color-scheme`、把结果写成 `<html>` 上的 `light` / `dark`。
- **默认「跟随系统」**，偏好存这台浏览器的 localStorage（`app:theme`），和日期偏好、侧栏收缩一个路数：它描述的是「这块屏幕上想看到什么」，跟账号无关，不为它开表。
- **首屏闪白必须在 Vue 之前解决**：`index.html` 里有一段同步的内联脚本，先把类名按 localStorage（或系统偏好）加上。等 `src/lib/theme.ts` 跑到时 bundle 已经下完解析完，深色用户早被白底闪过一帧了。两处读的是同一个键、同一种格式（裸字符串）。
- **`.dark` 整套比 shadcn 默认亮一档**（背景 `0.145 → 0.215`，卡片 `0.205 → 0.255`，muted/accent `0.269 → 0.315`，边框/input 的白色不透明度也跟着提）：默认那套接近纯黑，大片留白的页面上黑得发闷，卡片和背景几乎分不开。层级关系不动 —— 背景 < 侧栏 < 卡片/浮层 < muted/accent，每档差 0.04 左右；前景色仍是 `0.985`，背景提亮已经吃掉一点对比度，不能在这头再让。服务端渲染的登录页有自己一份内联 CSS，数值跟着对齐，否则从登录页进应用会明显亮一下。
- `color-scheme` 两套都要写（`:root` 是 `light`，`.dark` 是 `dark`）：滚动条、原生下拉这些浏览器自己画的东西只认它，少了它深色页面上会挂一条白滚动条。
- **vue-sonner 的 toast 不认 `.dark` 类**，它看自己的 `theme` prop，所以 `App.vue` 把当前解析出的主题传给 `Toaster`；不传的话深色下会弹出一个白底的 toast。
- localStorage 里的坏值退回「跟随系统」：`useColorMode` 会把存进去的词原样当类名加到 `<html>` 上，于是既不是 `light` 也不是 `dark`，页面回到浅色 —— 看着像「设置丢了」。
- 三档做成并排的按钮而不是下拉：只有三个选项、每档都有直观图标，展开一层才能换主题反而更慢。选「跟随系统」时下面补一行「当前是深色/浅色」，否则看不出这一档的结果是什么。

**日期与时间显示**：时区、语言、日期格式、时间格式、时制五项。

- **默认全部是「跟随浏览器」**，也就是没人动过设置之前，显示效果和没有这个功能时**完全一致**：locale 取 `navigator.languages`，时区取 Intl 的运行时默认值。
- 偏好只存在**这台浏览器**的 localStorage（`app:display-preferences`），不上服务端：它描述的是「在这台机器上想怎么看时间」，跟账号无关，也不值得为它开一张表。代价是换设备/换浏览器要重设一次。
- **改完立即生效，没有「保存」按钮**：偏好是响应式的，全站的时间都从 `@/lib/format` 出去，所以已经渲染出来的列表会自己跟着变。设置页底部的预览是活的（每秒走一次），换时区能直接看出差几小时。
- **时区那一项是能打关键字的下拉**（`src/components/settings/TimeZonePicker.vue`），不是普通 Select：全量 IANA 表四百多条，靠滚找不到。
  - 候选来自 `Intl.supportedValuesOf('timeZone')`（额外补一个 `UTC`），取不到时退回一小撮常用值。
  - 不输关键字时只摆常用的十几个（UTC、上海、香港、东京…），并说明「输入关键字可搜索全部」；开始输入才在全量里搜。
  - 四种搜法都认：IANA 名（`shanghai`）、把 `_` `/` 当空格的写法（`los angeles`）、中文别名（`上海`、`北京`）、GMT 偏移（`+8`）。空格分隔的多个词要**全部**命中，顺序不限。中文别名是一张手写小表——IANA 名里只有英文城市名，本地化全称又是「中国标准时间」这种不带城市的说法，两边都搜不到「上海」。
  - 结果最多显示 100 条，截断了会明说还剩多少条（截断却不说，看起来就像没搜到）。
  - 每条右侧显示当前 GMT 偏移；列表按偏移排序。方向键 + 回车可选中。
  - **搜偏移时常用时区排最前**：搜「+8」有十几个时区都对，按字母序第一个是南极科考站 `Antarctica/Casey` —— 技术上没错，但没人想要，看着就像搜错了。常用之间按 `COMMON_TIME_ZONES` 里写的人工顺序（上海在香港前），不是字母序。
  - **面板底部常驻一行「当前：xxx」**：搜索之后选中项多半已经被过滤掉，列表里那个 ✓ 就看不见了，得随时能确认自己到底设成了什么。
  - **界面显示的一律是「实际会生效」的值**，不是存进去的原始值。存了一个 Intl 不认的时区名时，格式化那边会退回「跟随浏览器」；选择器要是照原值显示，就成了「按钮上写着某时区、时间却按本机时区走」，而且完全看不出原因。
- localStorage 是用户能手改的，所以读出来的值先过一遍白名单（时区拿 `Intl` 试构造，档位按枚举），坏值退回默认 —— 一个拼错的 `dateStyle` 会让 `Intl` 抛 `RangeError`，把整个页面带崩。
- 调用方**显式传的选项优先**：某处一定要按 UTC 显示，就自己传 `timeZone: "UTC"`，偏好只填没说的那几项。
- **档位的示例是当场算的，不是写死的文案**：「短 / 中 / 长 / 完整」到底长什么样由 locale 决定（`medium` 在 zh-CN 下是「2026年8月18日」，en-US 下是「Aug 18, 2026」；而 zh-CN 的 medium 和 long 本来就几乎一样）。下拉里每一项括号里的样例走的是真正的 `formatWith`，所以选中它之后显示出来的就是括号里那个东西 —— 写死中文示例的话，英文 locale 下标签和实际对不上，看着就像「设置没生效」。「时制 - 跟随浏览器」同理，括号里写明它此刻跟到的是 12 还是 24 小时制。
- **「强制修改时区」这类浏览器扩展会让整块设置失效，界面必须直说。** 它们的通行做法是劫持 `Intl.DateTimeFormat`，把调用方传进去的 `timeZone` 一律换成自己设定的那个 —— 于是选哪个时区都显示同一个时间，时区列表里每一条算出来的偏移还全都一样（清一色 `GMT-7` 这种）。表现出来就是「设了时区没反应」，看着像应用坏了。`intlTimeZoneReliable()` 用一个探针识别它：同一个绝对时刻，UTC 和东京必然差 9 小时，两边一样就说明 `timeZone` 参数被忽略了。检测到之后设置页顶部出一条说明，并且不再显示那些算错的 GMT 偏移（预览注脚里的也一样）——摆一列错的偏移比不摆更误导。修不了它，只能说清楚。
- 预览上方标注**当前实际生效的时区（带 GMT 偏移）和语言**。时间和自己电脑上的对不上时，得先能分清是「设置没生效」还是「本来就该差这几个小时」。

## 3. 已知缺口

- 侧栏导航列表是**手写常量**，与路由表各维护一份，容易漏配：`/demo3`、`/hic`、`/example`、`/3d-cube` 都没有出现在侧栏里，`/example` 和 `/3d-cube` 甚至已经没有对应路由（视图文件 `Example.vue` / `Emu3DView.vue` 仍在）。
- 导航项名称大小写风格不统一（`canvas3d`、`richeditor` 对比 `Three Editor`、`3D导演台`）。
- 两个不同的导航项复用了同一个图标（`Sun`、`Video`）。
- `Game2048.vue` 的配色是 scoped CSS 里写死的十六进制值，不走主题变量，深色下和整站对不上；`src/styles/vue-flow.css` 里那套 `.basic-flow.dark` 规则则是从 Vue Flow 示例抄来的死代码（没有任何组件挂 `basic-flow` 类）。
- 登录页是服务端渲染的，只能跟随系统（`prefers-color-scheme`），读不到 localStorage 里的主题偏好 —— 手动设成浅色的人在登录页仍会看到深色。要修就得给那个页面加一段脚本，而它现在是刻意「零 JS」的。

## 4. 验收标准

- [ ] 未登录访问任意页面，在**服务端**就被 302 到 `/login?redirect=<原地址>`，浏览器不会加载任何前端产物；登录成功后回到原页面。
- [ ] 已登录时访问 `/login` 会被弹回目标页，不会停在登录页。
- [ ] 后端未配置 Keycloak 时，全站可直接访问，用户菜单里没有「登录 / 退出」这一组（设置、关于仍在）。
- [ ] 侧栏底部菜单能进「设置」，点「关于」弹出模态窗（地址栏不变），退出登录在同一个菜单里。
- [ ] 点「退出登录」先出确认框：取消 → 什么都不发生、仍在当前页；确认 → 跳去登出。
- [ ] 设置页改时区/格式后，项目列表等页面上的时间**不刷新**就跟着变；「恢复默认」后回到跟随浏览器。
- [ ] 设置页点「深色」立刻变深，切页面、刷新后仍是深色；点「跟随系统」后跟着操作系统的浅/深走，且改系统设置时页面不刷新就跟着变。
- [ ] 深色下刷新页面**不闪白底**（首屏就是深色）。
- [ ] 桌面端折叠 / 展开侧栏后，内容区宽度跟随变化且有过渡动画。
