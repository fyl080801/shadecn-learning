# CLAUDE.md

## Language

**Always reply in Chinese (中文).** All user-facing output — answers, explanations, plans, summaries, questions — is written in Chinese. Keep technical terms in their original English form (Vite, MikroORM, OIDC, NestJS, …).

Code identifiers, types and commit messages stay English. **Source comments in `apps/` and `packages/`, log/error messages shown to a developer or user, and test names are written in Chinese**, matching every existing file. `docs/` is Chinese too.

## Project

A Vue 3 learning sandbox: shadcn-vue UI, Three.js scenes, canvas mini-games, and one real feature — collaborative flow canvases (projects, Yjs, an agent). Requirements live in `docs/`, one file per requirement (index: `docs/README.md`); `docs/` says *what*, this file and `.claude/rules/` say *how*.

### Where a fact goes — `docs/` vs `.claude/rules/`

- **`docs/`** — product behaviour: features, interactions, what is on screen and where, which types / options exist, acceptance criteria, what is deferred. **A requirement change updates `docs/` only.**
- **`.claude/rules/`** — only constraints a reader of the code would get wrong by following intuition: the one write path, forbidden shortcuts, cross-module invariants, cycle rules, and *why* each holds. Don't restate behaviour; point at it (`docs/13` §3.7).
- **Test:** if a line would only change because a requirement changed, it belongs in `docs/`, not in a rule. Don't add component inventories, UI layouts, type lists or "not wired yet" notes to a rule.

## Monorepo layout

pnpm workspace. Every root command is a `pnpm --filter <pkg>` delegation.

- **`apps/web` (`@shadecn/web`)** — frontend (`src/` = `@/`, `vite.config.ts`, `index.html`, `login.html`, `components.json`). `devDependencies` only: it is bundled into `output/public`.
- **`apps/agent-runner` (`@learning/agent-runner`)** — the agent's `oci` sandbox image (`docs/31` §3.3), bundling `packages/agent-core`'s runner from source. `scripts/bundle-config.mjs` inlines `@learning/contracts` and `@learning/agent-core` and leaves every other package external, so anything server-side fails the boundary (`scripts/runner-boundary.mjs`, default-deny, pinned against a real bundle). **The image context is `apps/agent-runner/dist/`.** Its `dependencies` are the runner's four packages at `packages/agent-core`'s ranges (`test/runner-boundary.test.ts`). Not part of `pnpm build` (`.claude/rules/deploy.md`).
- **`apps/platform` (`@learning/platform`)** — a standalone NestJS service on `@nestjs/platform-fastify`, default port 3001. It hosts `apps/web` through `@learning/web`: `NODE_ENV=production` serves `output/public`, anything else mounts Vite (`pnpm dev`; `pnpm build` + `pnpm start`). Backend routes must stay under `/api`. `src/app.module.ts` and `src/platform-base.module.ts` list only static modules and hold no configuration: each module reads its own section of `<dataDir>/config.yaml` through `@learning/config` (sample: `apps/platform/config.example.yaml`), secrets come from the `.env` in the working directory (`apps/platform/.env` under `pnpm dev:platform`; sample: `apps/platform/.env.example`), and `main.ts` only calls `@learning/foundation`'s `bootstrapService`. Its database comes from `@learning/data-access`, its users and sessions from `@learning/session`, and `src/page-auth.module.ts` binds `SessionPageAuth` to `@learning/web`'s `WEB_PAGE_AUTH`. Every page and `/api` route requires a session, in dev too (`.claude/rules/auth.md`); login is OIDC and GitHub through `@learning/session` (`auth` and `server.origins` in `config.yaml`, secrets in `apps/platform/.env`, `docs/02` §3.3.2). It has no controllers of its own (its business API comes from `@learning/canvas`, `@learning/collab`, `@learning/storage`, `@learning/apps` and `@learning/agent`) and no image yet (`.claude/rules/deploy.md`). **It and the `@learning/*` packages don't depend on `@shadecn/*`** (pinned by a boundary test in each): `nest build` is plain tsc, so a source-only package would break once it sits under `node_modules` in an artifact (`ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`). The one remaining link is the frontend: `pnpm build:platform` builds `@shadecn/web` first. Its `tsconfig` leaves out `erasableSyntaxOnly` (decorators and constructor parameter properties need it off); its vitest project transpiles through swc, because the root vite's esbuild drops `emitDecoratorMetadata`.
- **`apps/collab` (`@learning/collab-service`)** — collaboration replicas: `main.ts` + `AppModule` only (`docs/30` §3), no pages, login flow or canvas REST. It refuses to start unless `cluster.mode: redis` and `database.schemaSync: off`. `scripts/dev-front.mjs` (`pnpm dev:front`) runs one platform (`main-without-collab`, a separate entry whose root is `PlatformSplitModule`, i.e. `PlatformBaseModule` plus a check refusing anything but `cluster.mode: redis`), the replicas and a front proxy from built artifacts. The agent, storage and apps exist only on the platform: a replica's dependency closure has none of them (`test/package.test.ts`), the panel's SSE goes through the proxy and the runner connects to the platform's port directly (`.claude/rules/agent.md`, `cluster.md`). Same tsconfig `paths` and vitest shape as `apps/platform`; not part of `pnpm build`.
- **`packages/config` (`@learning/config`)** — the global Nest module `ConfigModule` + `ConfigService`: reads `<dataDir>/config.yaml` and `<cwd>/.env` during startup (`dataDir` = env `DATA_DIR`, else `<rootDir>/data`; `rootDir` = the nearest `pnpm-workspace.yaml` above `process.cwd()`, else cwd). A missing file is an empty config; bad YAML or a non-mapping top level refuses to start, and the error carries the path, never the content (`yaml`'s default messages are off). `.env` only feeds `ConfigService.env(name)`: process env wins, it is never written back to `process.env` (secrets don't reach Vite or child processes), and `NODE_ENV` / `DATA_DIR` ignore it. Under `pnpm dev` / `pnpm start` cwd is `apps/platform`, so that's where the `.env` goes. It validates no section: **each section's validation and defaults belong to the module that reads it.** Business modules inject the global `ConfigService` without importing `ConfigModule`, and tests swap it through `@learning/config/testing`'s `testConfigModule(values, options)` (not exported from the main entry). **The class is the DI token, so a process must hold one copy**: business packages declare it as a peer (`packages/data-access/test/dist.test.ts` runs the real output against it). Vitest aliases must list `@learning/config/testing` before `@learning/config`. Compiled with tsc like `@learning/web`.
- **`packages/web` (`@learning/web`)** — the static Nest module `WebModule`: hosts a frontend as Vite middleware (`dev`) or built static files (`static`), Fastify only. Its section is `web`; `mode` follows `isProduction` and can't be configured. The page gate is on unless `web.auth: false`; something must then provide `WEB_PAGE_AUTH` (`.claude/rules/web-shell.md`). Unlike `@shadecn/*` it is **not source-only**: decorators can't be type-stripped, so it compiles to `dist/` and consumers run that (`apps/platform`'s `build` / `dev` build it first; its `dev` watch does not pick up changes here at runtime — rebuild and restart). The `source` export condition (`customConditions` in the consumer's `tsconfig`) and a vitest alias let typecheck and tests use the source without a build. `vite` is an optional peer: only `vite-host.ts` loads it, through a dynamic `import()`; a static one would break production.

A controller declaring the same path fails the start (Fastify's duplicate route). Compiled with tsc like `@learning/web`, built first by `apps/platform`.

Compiled with tsc like `@learning/web`, built first by `apps/platform`.

It holds only the methods its callers use (collab, canvas; `compareAndSet` and `SharedLog` for the agent's occupancy and run registry, `docs/31` §4.4); `ioredis` loads through a dynamic import, so `single` never touches it. Consumers declare it as a peer: `Cluster` is a DI token. Compiled with tsc like `@learning/web`, built first by `apps/platform`.

Its section is `database` (`url`, `schemaSync`). It owns `User`, the column helpers, `openOrm` and the schema-sync guard; **every other entity is registered by the module that owns it** through `{ provide: DATA_ACCESS_ENTITIES, useValue: [...] }` (`.claude/rules/database.md`), so a process without a module has no tables for it. Compiled with tsc like `@learning/web`, built first by `apps/platform`. Consumers declare this package as a peer too: its `User` and `DATA_ACCESS_ENTITIES` must be one copy.

### Invariants — each is a bug if undone

- **Tailwind's source scan is rooted at `apps/web`**; class names outside it are not detected.
- **`@shadecn/shared` is a `workspace:*` devDependency of `apps/web` and peer-depends on `yjs` and `@dagrejs/dagre`.** Exactly one yjs copy per bundle, or `instanceof Y.Map` is always `false` and canvases go blank. Guaranteed by pnpm linking + the frontend's `resolve.dedupe`; pinned by `apps/web/src/test/lib/sharedYjs.test.ts` (and `packages/collab/test/shared-yjs.test.ts` for `@learning/contracts`).
- **Writing `packages/shared`**: relative imports carry `.ts`; no DOM or Node API (`lib: ["ES2020"]`, `types: []`: the frontend recompiles it under its own config and `packages/contracts` compiles a byte copy under another). Tests use `tsconfig.test.json` so vitest's Node types don't switch the guard-rail off.
- **Lockfile ranges were kept identical to the pre-monorepo ones** (a fresh resolve drifts `reka-ui` to 2.10.1). Don't `pnpm update` casually; read the lockfile diff of any install.

## Commands

- `pnpm dev` (= `dev:platform`) — whole app (Nest + Vite middleware, watch) on http://127.0.0.1:3001. One process, one port, no proxy, in dev and prod. It builds every `@learning/*` package first; its watch doesn't pick up later changes in them, so rebuild and restart.
- `pnpm build` (= `build:platform`) — `build:client` (`vue-tsc -b` + `vite build` → `output/public`), then the `@learning/*` packages and `nest build` → `apps/platform/dist`.
- `pnpm start` (= `start:platform`) — run the platform with `NODE_ENV=production`; `pnpm preview` = build + start.
- `pnpm dev:front` — one platform, the collab replicas and a front proxy from built artifacts (`build:collab-service` builds the replica alone); Redis and PostgreSQL are yours to start.
- `pnpm build:agent-runner` — typecheck + `@learning/agent-core`'s typecheck + esbuild of the runner → the image context `apps/agent-runner/dist/`; fails if the closure crosses the boundary.
- `pnpm build:agent-runner-image` — `build:agent-runner`, then build `learning-agent-runner:latest` (`AGENT_RUNNER_IMAGE` overrides) with podman / docker; extra args go to the build. Rebuild it whenever the runner or the gateway protocol changes.
- `pnpm typecheck:<x>` — `platform`, `collab-service`, `agent-runner`, `shared`, `learning-web` (`@learning/web`), `agent-service` (`@learning/agent`), and each other package by directory name (frontend is checked by `vue-tsc -b` in `build:client`).
- `pnpm test` (`test:watch`, `test:coverage`) and `pnpm test:<x>` — `client` (`apps/web`), `shared`, then the same names as `typecheck:<x>`.
- `pnpm lint` / `pnpm lint:fix`.
- **No migration files and no sync command**: the schema syncs during service startup, additive only; a lossy change refuses to start with the statements printed (`.claude/rules/database.md`). Use `sqlite3` / `psql` to look at the database.

Before the first run: `apps/platform/config.example.yaml` → `data/config.yaml`, `apps/platform/.env.example` → `apps/platform/.env`. Every page needs a session, so a login provider must be configured (`.claude/skills/verify/SKILL.md` has one that works without an IdP).

## Architecture

**Stack:** Vue 3 + TypeScript + Vite + Tailwind CSS v4 + shadcn-vue (new-york). `@/` → `apps/web/src/`; shared code is imported as `@shadecn/shared/<subpath>`, never through `@/`. Frontend, `/api/*` and `/ws/collaboration` are same-origin in every mode — use relative paths.

Details live in `.claude/rules/`, one file per area, each loaded when you touch a path it lists. **Read the matching file before changing code in that area** — each is a set of invariants where the obvious change is a known bug:

- **Canvas editor** — `flow-editor.md`: views and workspace, editor context, node-type registry and node-kit, selection / groups / snapping, the store as a *projection of a Y.Doc* (`store.mutate()` is the only write path), five-group node schema, collection keys, drafts, viewport state, personal canvases.
- **Collaboration** — `collab.md`: data vs feedback layer, Hocuspocus mount and timings, persistence (read → merge → CAS; **a failed store must propagate**), quota, awareness, one-window-per-user, terminal close codes, revocation, write gate, WebSocket `Origin`.
- **Frontend shell** — `web-shell.md`: router + layouts, frontend auth and popup re-login, frontend hosting and the login entry, the page gate, shadcn-vue (`Button.vue` is hand-edited), `@lucide/vue` only, theme gotchas, views.
- **Auth** — `auth.md`: OIDC + GitHub BFF, providers, per-request callback origin, sessions, confirmed account linking, identity is `(provider, subject)` never email, the profile step, avatars.
- **Database** — `database.md`: entities, SQLite *or* PostgreSQL, entity rules, Prisma habits that are now bugs, schema-sync guard, `containsIgnoreCase()`.
- **Clustering** — `cluster.md` · **Deploy** — `deploy.md` · **Tests** — `testing.md` · **Agent** — `agent.md` · **Apps** — `apps.md`.

When a fact goes stale, fix it where it lives — each fact has one home. If a stale fact sits in a rule but is really a requirement, move it to `docs/` instead of rewriting it in place.

## Dependencies

Each package declares only what it needs; **the runtime set of an artifact is its app's `dependencies` plus what its `@learning/*` packages declare themselves** (`apps/platform`, `apps/collab`, `apps/agent-runner`), everything else is `devDependencies`.

- A package a **backend package** imports → that package's own `dependencies`. **A class that is a DI token, or a library that must be one copy per process (`yjs`), is a `peerDependency`** instead, and the app declares it: `@learning/config`, `@learning/cluster`, `@learning/data-access`, `@nestjs/*`, `@mikro-orm/core`, `yjs`. The per-package reasons are in the layout above.
- A **frontend** package → `apps/web` `devDependencies` (`pnpm --filter @shadecn/web add -D`; the shadcn-vue CLI, run from `apps/web`, writes there).
- Never hoist to the root unless it's repo-wide tooling (eslint, typescript, vitest + coverage, jsdom). The root also holds `pnpm.neverBuiltDependencies: ["better-sqlite3"]` (`.claude/rules/deploy.md`).
- `@mikro-orm/*` is pinned to exactly `7.2.5`; both DB drivers (`@learning/data-access`) and both cluster packages (`ioredis` in `@learning/cluster`, `@hocuspocus/extension-redis` in `@learning/collab`) are ordinary dependencies, because DB and mode are runtime choices.

## Conventions

- TypeScript strict with `noUnusedLocals`, `noUnusedParameters`; `apps/web` and `packages/shared` add `erasableSyntaxOnly`, which the Nest code can't have (decorators). All Vue components use `<script setup lang="ts">`.
- Tests live in `apps/platform/test/`, `apps/collab/test/`, `apps/agent-runner/test/`, `apps/web/src/test/`, `packages/*/test/`, mirroring what they cover. Relative imports in the `@learning/*` packages and the Nest apps carry `.js`, in `packages/shared` `.ts`. Import `describe` / `it` / `expect` / `vi` from `vitest` (no globals). Name tests by the behaviour constrained ("未登录 → 401").
- **Backend logs are `console.*` with a `[prefix]`** (`console.warn('[collab] …')`); there is no logger object to inject.
- **Time is UTC everywhere except on screen.** The DB stores absolute instants; stores map rows out with `toISOString()`, so the wire format is always ISO with `Z`. **The frontend never formats a date inline** — use `apps/web/src/lib/format.ts` (`formatDateTime` / `formatDate` / `formatTime` / `formatWith(value, options)`; all render `-` for unparseable input).
  - The defaults come from `apps/web/src/lib/preferences.ts` (browser-local `app:display-preferences`; each field defaults to `AUTO` = follow the browser). `format.ts` reads the reactive `resolvedDisplayPreferences`, so changes re-render live. A **caller-supplied option always wins**, and stored values are **validated on read** (a bad `dateStyle` makes `Intl` throw).
- **On the canvas path, time is a number** — UTC epoch ms (`FlowNodeData.createdAt`, `FlowEdgeData.createdAt`). Stamped by each browser's own clock, so never order across clients by it.
- **One click, one request — every write-side interaction goes through `apps/web/src/composables/useAsyncAction.ts`.** `const { run, pending } = useAsyncAction(fn, { errorMessage })`; `run()` marks pending **synchronously**, so a same-tick second click is dropped (`:disabled` lands a render too late, and Enter / `@select` / blur / `AlertDialogAction` have no button). Bind `<Button :loading="pending">`. `run` never rejects and toasts errors (`onError` overrides), so action bodies carry no `try/catch`. Lists pass `key: (item) => item.id`. **Write `@click="submit()"`, not `@click="submit"`** (the latter passes the MouseEvent). Reads are out of scope.
- **Client-generated ids go through `apps/web/src/lib/id.ts`'s `createId(prefix)`** (`<prefix>_<base36 time>_<random>`); the random tail keeps two clients from minting the same id in one millisecond.
