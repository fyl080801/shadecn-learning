# REQ-ASSET-THUMB 画布资源缩略图：图标 / 低清 / 原图三档

> 状态：**已实现**。上传与地址的现状见 [REQ-CANVAS §3.7「资源上传」](13-flow-canvas-management.md)；私有访问（规划中）见 [REQ-ASSET-PRIVATE](25-private-asset-access.md)。

## 1. 背景

画布上的图片节点、视频节点的预览图、agent 消息里已发出的附件，现在一律直接加载**原图**：

- 一张几 MB 的照片在画布上只占两三百像素宽，几十个节点就是几十张原图同时解码，首屏慢、内存高；
- 对话里的附件缩略块只有几十像素，也在拉原图；
- 以后有了图片提及（见 §4），小小一枚 badge 拉原图更不划算。

对象存储（集群内的 MinIO）**没有图片处理能力**：不像阿里云 OSS 的 `x-oss-process`、七牛的 `imageView2` 那样按 URL 参数现场缩放。它的 Bucket Notification（写入后异步通知外部 worker）和 Object Lambda（读时经 webhook 改写、不缓存）都不合适（异步，或每次读都现算）。所以缩略图由**本服务在上传时生成**，作为普通对象和原图存在一起，只用标准 S3 接口，换存储也不受影响。

## 2. 三档

| 档 | 名字 | 规格 | 用在哪 |
|---|---|---|---|
| 图标 | `icon` | 长边 ≤ 128px，webp，取第一帧（动图也是静止的） | 对话里已发出的附件缩略块、图片 / 视频提及（规划中，见 §4） |
| 低清 | `low` | 长边 ≤ 768px，webp，动图保留动画 | 画布节点（图片、视频预览图；缩得很小时换成 `icon`，见 §4.1）、节点底部的产出缩略图 |
| 原图 | `original` | 上传的原文件，不动 | 产出的大图预览（框外右侧，「展开预览」）、agent 看图、下载 |

- 只缩小、不放大：原图本身比档位还小时，按原尺寸转成 webp。
- 按 EXIF 方向转正（手机竖拍的照片在缩略图里不会躺倒）。
- 高宽比与原图一致：节点尺寸按图片比例走（`media-fit.ts`），用低清图量出来的比例和原图相同。

## 3. 存储

### 3.1 对象键

缩略图和原图放在同一个目录，文件名是原图的 uuid 加 `@<档>.webp`：

```
<prefix>/assets/ab/cd/<uuid>.png         原图（不变）
<prefix>/assets/ab/cd/<uuid>@icon.webp   图标
<prefix>/assets/ab/cd/<uuid>@low.webp    低清
```

- **节点里只存原图地址**（`data.src` / `data.poster`），档位地址按上面的规则从原图地址推出来，不进 Y.Doc。以后调档位规格、加档都不用改文档数据。
- 推导规则只有一份（`@shadecn/shared/canvas` 的 `assetVariantPath`），前端拼地址、服务端拼键都用它。只认我们自己拼出来的素材键形状（统一素材目录 + uuid 两级目录 + uuid 文件名）；外部链接、`data:`、`blob:`、早先 `projects/…` 分层的老键、SVG 一律**没有档位**，直接用原图。
- 档位键**不是**客户端能写的键：分片上传每一步带回来的键仍只认原图形状（`isAssetKey`），没法借分片上传覆盖缩略图。

### 3.2 生成时机

**上传接口在回包之前同步生成**，与原图、上传记录同一个顺序约束：原图写进 S3 → 生成并写入各档 → 记上传记录 → 回包 → 前端把地址写进节点。同画布的其他人看到节点时，缩略图已经在了。

- **一次传完的上传**（`POST /assets`）：字节已经在服务端内存里，直接生成。
- **分片上传**：完成（`complete`）之后，按 S3 上实际拼出来的类型判断；是要生成的图片并且不超过 32MB，就把对象读回来再生成；超过的不生成。
- **生成哪些类型**：`image/jpeg`、`image/png`、`image/webp`、`image/gif`、`image/avif`。SVG 是矢量图，不生成；其他图片类型（HEIC、BMP…）和视频不生成。
- **视频**：不在服务端截帧（不引 ffmpeg）。视频节点上传时浏览器本来就会截一帧当预览图，单独作为一张 JPEG 上传，这张预览图按图片走，自然有三档。
- **防解压炸弹**：原图超过 6400 万像素（约 8000×8000）不生成。
- **生成失败不算上传失败**：原图已经存好，缩略图只是锦上添花。失败（图片损坏、超过像素上限、写 S3 出错）只记一条日志，回包照常 201，前端回退到原图（§4）。
- 回包 `UploadedAsset` 多一个 `variants` 字段：这次实际生成了哪几档（可能是空数组）。仅供展示、调试，前端不靠它判断有没有缩略图（节点里不存它，协作者也拿不到）。

### 3.3 补档：取不到时按需补生成

老数据、生成时写 S3 失败、缩略图对象被删掉……桶里缺某一档时，**前端加载这一档失败（404）就请服务端补**，不靠一次性脚本扫存量。

- 接口：`POST /api/flows/:flowId/assets/variants` `{ src }`（`src` 是节点里存的原图地址），回 `{ variants }` = 补完之后这张图**有的**档。鉴权同上传（画布成员，否则 404）。
- 只补我们自己的素材：`src` 必须是本服务桶里、素材目录下、我们拼出来的键（外部链接、档位地址 → 400），并且**经本服务上传过**（有上传记录，哪张画布都算 —— 复制出来的画布仍指着原画布传的图；没有记录 → 404）。
- 先逐档查对象在不在：都在就什么都不做；缺的才读回原图、**只生成缺的那几档**。生成规则同 §3.2（类型名单、32MB、像素上限），补不出来回已有的档（可能是空数组），不算错误。
- 服务端去重、限流：同一张原图同时只补一次（多人同时打开同一画布都等同一次）；整个进程同时最多补 2 张（老画布一打开几十张没缩略图的图，别一下子全读进内存）；补不出来的原图记 10 分钟，这期间再请求不读原图。存储出错回 502。
- 前端：同一张原图整页只请求一次（图标、低清同时 404 也只一次）；成功就记住结果，请求失败（网络、5xx）不记，下次 404 再试。只在画布编辑器里补（接口挂在画布下）。

## 4. 显示：按档取地址，取不到退回原图

- 前端用统一的 `<AssetImage :src="原图地址" size="icon | low | original">` 显示资源图片：推得出档位地址就先加载它；**加载失败（404，比如老数据、生成失败、SVG 以外的冷门格式）自动退回原图**，原图也失败才算加载失败（照常触发 `error`）。在画布编辑器里同时请服务端补档（§3.3）；补出了要的那一档、图也没换，就换回缩略图（每一档只换回一次：服务端说有、浏览器却还是加载失败，就留在原图）。
- 各处用的档位见 §2 表格。

### 4.1 画布节点：渐进加载 + 按缩放取档

图片节点、视频节点的预览图用 `CanvasAssetImage`：

- **毛玻璃占位**：目标档还没加载完时，底下先垫一张 `icon` 档，做模糊处理（放大一点，盖住模糊后发虚的边）；目标档加载完盖上去、撤掉占位。图标只有几 KB，几乎立刻出来，节点不再是一块空的灰底。
- **先图标、后目标档**：一张图的 `icon` 档有结果（加载完或失败）之前，目标档不发请求。画布初次打开时所有资源节点先请求图标、铺满毛玻璃，再逐个换成清晰的；不排队的话几十张低清图和图标抢连接，图标不一定先到。只在每张图第一次时等，之后缩放换档不再等；换了图（`src` 变了）重新等。
- **按缩放取档**：节点在屏幕上的长边 = 节点长边 × 画布缩放 × 设备像素比（物理像素）。不超过图标长边的 1.5 倍（128 × 1.5 = 192）就只用 `icon`，否则用 `low`。例如 320px 宽的节点在普通屏缩到 60% 以下、高分屏缩到 30% 以下就换成图标。画布上从不加载原图。
- **跨阈值时换档**：缩小换回 `icon`（之前已经作为占位加载过，几乎立刻好）；放大换到 `low`，加载期间露出毛玻璃占位。
- **没有缩略图**（老数据、外部链接）：没有占位，目标档退回原图，照旧边下边显示；是我们的素材就顺带补档（§3.3），补好后换成目标档，下次打开就有毛玻璃占位了。
- **节点尺寸**：按资源比例记尺寸（REQ-CANVAS §3.7）时，`icon` 档量出来的只在节点还没有尺寸时用来记一个近似值；已有尺寸就不按它改，免得来回缩放时节点尺寸跟着抖。上传中的本地预览（`blob:` 地址）、视频本身（`<video>`）不受影响。
- **对话里已发出的附件**：图片附件用 `icon` 档。视频附件没有预览图，仍按现在的方式显示视频第一帧。
- **输入区里待发的附件**：还没上传完，用的是本地预览（`blob:`），照常显示，不涉及档位。
- **图片 / 视频提及（规划中，不在本期）**：现在还没有图片提及；提及节点的 badge（`@` 节点）只显示类型图标，本期不改。将来带 prompt 输入框的节点按连线顺序生成 `<image 1>` `<video 1>` `<text 1>` 这类提及时，图片 / 视频提及里的小图用 `icon` 档（图片取 `src`，视频取 `poster`），经 `AssetImage` 显示。

## 5. 与私有访问的衔接

[REQ-ASSET-PRIVATE](25-private-asset-access.md) 实施后，资源地址改为 `/api/assets/<key>`。到时档位用查询参数表达：`/api/assets/<key>?size=icon`，服务端判权后 302 到对应那一档的签名 URL；档位的对象键规则（§3.1）不变，前端只换 `assetVariantPath` 一处的拼法。

## 6. 验收

1. 上传一张 4000×3000 的 JPEG：桶里多出 `@icon.webp`（长边 128）和 `@low.webp`（长边 768），回包 `variants` 为 `["icon", "low"]`。
2. 画布图片节点加载的是 `@low.webp`；对话里已发出的图片附件是 `@icon.webp`；展开预览加载原图。
3. 上传视频：预览图有三档；画布节点显示预览图的低清档。
3a. 打开图片多的画布：每个节点先出现模糊的小图（网络面板里 `@icon.webp` 都排在 `@low.webp` 前面），低清图到了再变清晰；把画布缩到很小，节点换成图标档（网络面板里只有 `@icon.webp` 请求），放大回来先模糊、再清晰。
4. 上传 SVG、超过 32MB 的分片图片、损坏的图片：上传成功，没有缩略图，各处显示原图。
5. 老数据（没有缩略图的键）：先请求档位 404，随即退回原图，界面上看不出区别；同时发出一次补档请求（同一张图整页只一次），补好后节点换成低清档，桶里多出 `@icon.webp` / `@low.webp`；刷新后直接加载缩略图、不再 404。
5a. 删掉某张图的 `@low.webp` 再打开画布：补档只生成 `low`，`icon` 不动。损坏的图片补不出来：回 `variants: []`，一直显示原图，10 分钟内再打开不会再读原图。
6. 分片上传带一个 `…@icon.webp` 形状的键 → 400。

## 7. 本期不做

- 视频服务端截帧；对话里视频附件的预览图。
- 删除原图时连带删缩略图（目前没有删除对象的流程，见 REQ-ASSET-PRIVATE §5.4）。
- 按任意分辨率取图（imgproxy 一类的现场缩放服务）。
