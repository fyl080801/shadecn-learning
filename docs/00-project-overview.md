# 项目总体定位与共性约束

## 1. 项目定位

这是一个 **Vue 3 技术验证沙盒**：在同一个应用里并行探索多条技术线，验证它们能不能在真实工程约束（TypeScript 严格模式、统一鉴权、单进程部署、可测试）下共存。

它不是一个面向最终用户的产品，因此：

- 页面之间**没有业务关联**，每个视图是独立的验证载体；
- 允许存在只搭了架子、尚未填内容的页面；
- 但**基础设施必须是生产级的** —— 鉴权、服务端、构建、部署、测试这几条线不能"演示级"糊弄过去。

## 2. 技术线清单

| 方向 | 验证目标 | 对应需求 |
|---|---|---|
| UI 体系 | shadcn-vue + Tailwind v4 能否支撑复杂工具型界面 | REQ-SHELL、REQ-3DEDITOR |
| 身份认证 | 无 `jose` / `openid-client` 依赖，手写 OIDC BFF 是否可行 | REQ-AUTH |
| 服务端形态 | 一个 Node 进程同时承载 API + WebSocket + 前端，是否够用 | REQ-SERVER |
| 实时协同 | Yjs 在自建 WebSocket 服务上的可用性 | REQ-COLLAB |
| 3D | Three.js 官方 editor 移植到 Vue + TS 的可行性，以及在其上做垂直业务 | REQ-3DEDITOR、REQ-DIRECTOR |
| 富文本 | 不依赖 Slate/ProseMirror/Tiptap，自研插件式内联编辑器 | REQ-PROMPT |
| 图编辑 | Vue Flow 的交互定制能力 | REQ-FLOW |
| Canvas | 原生 Canvas 游戏、CSS 3D、`drawElementImage` 等浏览器新能力 | REQ-DEMO |

## 3. 共性功能需求

以下要求对**所有**页面和模块生效，各需求文档不再重复。

### 3.1 登录

- 除服务端渲染的 `/login` 外，所有页面必须登录后才能访问；拦截发生在 Node 中间件里，未登录连前端产物都拿不到，详见 [REQ-AUTH](02-auth-keycloak.md)。
- 浏览器端**不得**持有任何 token；所有受保护请求依赖 httpOnly Cookie。

### 3.2 同源

- 前端、`/api/*`、`/ws/*` 在开发与生产环境下**必须同源同端口**。
- 前端代码一律使用相对路径请求，禁止出现硬编码的 host / 端口 / 协议。

### 3.3 布局

- 页面在 `App.vue` 的侧栏布局内渲染，可用高度为视口高度减去布局占位；页面**自己**负责内部滚动，不得把 `body` 撑出滚动条。
- 需要整屏的工具型页面（编辑器、导演台）必须填满可用区域，不留外边距。

### 3.4 主题

- 亮色 / 暗色两套主题通过 `src/style.css` 中的 CSS 变量（oklch）定义。
- 新增组件必须使用语义化颜色变量（`bg-card`、`text-muted-foreground` 等），禁止写死具体色值。

### 3.5 语言

- 面向使用者的界面文案用中文；代码标识符、注释以外的源码内容用英文。
- 已移植的第三方界面（Three.js editor）沿用其原有的多语言机制，不强制汉化。

## 4. 技术栈约束

| 约束 | 说明 |
|---|---|
| 包管理器 | 仅使用 pnpm |
| TypeScript | strict + `noUnusedLocals` + `noUnusedParameters` + `erasableSyntaxOnly`，不允许用 `// @ts-ignore` 绕过（生成代码除外） |
| Vue | 全部组件使用 `<script setup lang="ts">` |
| 路径别名 | 前端一律用 `@/`；`server/` 内部使用带 `.ts` 扩展名的相对导入 |
| 新增运行时依赖 | 需要有明确理由；能用现有依赖或标准库解决的不引入新包 |

## 5. 本期不做

- 多租户、组织 / 团队概念。
- 国际化框架（i18n）——目前中文硬编码即可。
- 移动端专门适配（侧栏做了窄屏收起，页面内容不保证移动端可用）。
- 任何形式的埋点、监控上报。

## 6. 待确认事项

- 沙盒里的哪些模块要沉淀为可复用的独立包（`prompt-input`、`three-editor` 都是候选）。
- 是否需要引入状态管理库（目前靠模块级 `ref` 单例，模块变复杂后可能不够）。
