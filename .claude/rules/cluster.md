# Single vs multi-replica (`packages/cluster` = `@learning/cluster`, `docs/14-clustering.md`)

- `cluster.mode` (`single` | `redis`): explicit value, else inferred from having an address (`PLATFORM_REDIS_URL` in `.env`, else `cluster.url`), else `single`. **Database and Redis are configured independently.** `redis` without an address refuses to start; `redis` + SQLite only warns in dev (a legit way to exercise Redis locally) and refuses in production.
- Shared state is the abstract classes in `shared-state.ts`: `SharedMap<V>` (`get` / `set` / `claim` / `compareAndSet` / `delete` / `deleteIfEquals` / `entries` / `deleteByPrefix`, TTL), `SharedLock` (`shared-lock.ts`), `SharedLog<V>` (ordered log: `append`, `read`, `wait`, `expire`), `SharedChannel<V>` (`publish` / `subscribe`). `memory.ts` and `redis.ts` pass the same contract suite (`test/shared-state.test.ts`, `shared-lock.test.ts`, `shared-log.test.ts`; Redis when `PLATFORM_TEST_REDIS_URL` is set). `health()` is **synchronous with no network call**.
  - **`SharedLog`**: one Redis stream per key; `append` is `XADD MAXLEN <n>` (exact, not `~`: small logs, deterministic trim) + `PEXPIRE` of the whole stream in one `MULTI`. Ids are opaque cursors, never parse them; a cursor that fell off a trim just yields what's left, so **readers detect gaps themselves** (sequence numbers in the value).
  - **`SharedChannel`** is fire-and-forget: only subscribers listening *at that moment* get a message (nothing before `subscribe`, nothing during a subscriber reconnect). Anything that must not be lost needs a second source of truth the sender can check (the agent's stop falls back to "registry gone = run gone").
- **Every method is async, even in memory**, so call sites never change.
- **The bus is scatter-gather with a mandatory fallback** (`bus.ts`): a request goes to every instance registered for the token and waits for all or the timeout; `missing` / `failures` are normal, and no responders is an immediate empty result. The local handler is called directly, so one process never touches the channel. **Cross-process calls are bus requests or the access signal, never HTTP between processes**, and a reply that never comes must degrade (the flush before duplicating a canvas falls back to reading the database), not hang.
- `redis.ts` is dynamically imported, so `single` never loads ioredis.
- Multi-replica collab = `@hocuspocus/extension-redis` (pub/sub for updates + awareness, redlock around `onStoreDocument`, `afterLoadDocument` waits for a peer's state). **socketId gets an `instanceId:` prefix** (Hocuspocus's is only per-process unique; a collision drops the real owner's awareness as impersonation). No sticky sessions.
- **The same update fires `onChange` on every instance holding the room.** Any per-update side effect (webhooks, notifications, metrics) must skip `isRelayedUpdate(origin)`, or it fires once per replica (and the copy carries no author `context`).
- **Quota is eventually consistent**: `CollabQuota.locked` runs synchronously per message on a local `Map`; the verdict is pushed to the shared layer fire-and-forget and pulled back on the 1–5s re-measure tick.
- Local: start Redis and PostgreSQL yourself, then `pnpm dev:front` (`apps/collab/scripts/dev-front.mjs`). It holds no configuration: each process's `config.yaml` sits under `DEV_FRONT_ROOT` (default `data/dev-front`, header of the script). The platform runs `schemaSync: apply` and must be ready before the replicas (`off`) start.
- **No lazy proxies**: `Cluster` comes through DI, so it is ready before anyone can inject it. `SharedLock.run` semantics: `docs/14` §3.2.
- **`SharedLock.run` has no default TTL**: `ttlMs` must exceed the task's worst case, or the lock expires and the task runs concurrently. A failed acquire throws `SharedLockUnavailableError` with the task not run; **never fall back to running it unlocked**, that is the bug the lock exists to prevent. `fallback` must get its answer without assuming the winner succeeded: the lock may have opened by expiry, and a Redis failure while waiting also lands there.
- **The Redis connection is tuned for the request path, don't relax it**: `enableOfflineQueue: false` (fail instead of queueing through an outage), `commandTimeout` (the only thing that frees a command when the peer stops answering without closing, measured with a paused container), `autoResendUnfulfilledCommands: false` (a `SET NX` the caller gave up on must not be resent after a reconnect: it would leave a lock nobody releases).
- **A timed-out `SET NX` may still run**: when the peer only stopped answering, the command sits in the socket and executes on recovery, leaving a lock nobody releases, and every waiter sits out the TTL (measured: pausing the Redis container). So a failed acquire also sends the token-checked release, which the same connection orders after the `SET`. If the connection dropped first, the lock simply waits out its TTL.
- **The connection closes in `onApplicationShutdown`**, like the ORM: requests draining through HTTP close may still hold a lock.
- **`cluster` must not import a business package**, `data-access` included. `redis` + SQLite is a rule about two sections, so the rule is `assertClusterDatabase` here and the wiring is `@learning/session`'s `ClusterDatabaseCheckModule` (session already peers on both). **Every root module imports it.**
- **`Cluster.redisUrl` exists for Hocuspocus's Redis extension and nothing else; it may hold a password, so it never reaches a log.** The extension opens its own connections because `redis.ts`'s are tuned for the request path (no offline queue, no resend) and a subscriber can't share them.
- **`compareAndSet` is a Lua script, and its rejection doesn't mean it didn't run** (same as the lock's `SET NX`): the peer may only have stopped answering, and the script executes on recovery. `false` means someone else holds the key, a rejection means nobody knows; callers mustn't read one as the other. Without `ttlMs` the key becomes persistent, it does not keep its old TTL.
- **`SharedLog.wait` is the one thing not on the main connection, and its connections are tuned the opposite way.** `XREAD BLOCK` would stall everything queued behind it, so `BlockingPool` lends a connection (≤ 16 busy, ≤ 4 idle, beyond the cap it polls `XRANGE` until `blockMs`). `commandTimeout` is off, or every block over 2 seconds is cut. That leaves nothing to free a silent peer, so each wait has its own watchdog that disconnects the connection (the handshake can hang too: TCP accepts while the container is paused). `retryStrategy` returns null: with `autoResendUnfulfilledCommands: false` a reconnect drops the in-flight command without rejecting it, and the reader waits forever. So a broken connection is discarded, which is also why `health()` doesn't count these: nothing stays broken.
- **Closing wakes every wait with `[]`, and a later `wait` rejects in both backends.** Returning `[]` forever would turn the caller's loop into a spin that never yields. The pool only ever `disconnect`s: a connection blocked in `XREAD` can't answer `QUIT`. This doesn't release an HTTP connection: `Cluster` closes after HTTP in `onApplicationShutdown`, so an SSE relay blocked in `wait` must be ended before that by its owner.
- **The memory log sweeps expired logs when creating one**: nothing deletes a log (TTL only) and a reader that left never touches it again, so in a long-running `single` process each run would otherwise stay in memory.
- **Add a method only when a caller exists**: `SharedCounter` and `Bus.dispatch` are absent on purpose, and so are `SharedLog`'s `delete` and `read`'s `count`.
- **Memory stores encoded values and shares a namespace within a backend**, so a read returns a new object and two `createMap(ns)` calls see one table, as on Redis. Otherwise a test passes on memory and the behaviour differs on Redis.
- **`apps/collab/scripts/front-proxy.mjs` forwards streams, and `pipe` carries no failure in either direction.** A client disconnect must destroy the upstream request: the platform's SSE only unsubscribes on that connection's `close`, so otherwise "a disconnect only unsubscribes" holds for no one behind the proxy and the subscription lasts until the round ends. An upstream that dies mid-response must destroy `res`: `pipe` leaves it hanging, and `end` or an error line would read as a clean finish once headers are out. `flushHeaders` is there because Node otherwise holds an SSE's headers until the first frame, and on a rejoin that can be a long time.
- **A replica running `single` is the data-loss case of `docs/14` §2**, and a platform in `single` can't reach replicas either (revocation and flush go through this layer). `apps/collab`'s `AppModule` refuses `single`; the platform can't, since one process with `single` is its default, so `docs/30` §3 says it must switch too.
- **`Bus.request` must not reject on a shared-layer failure**: it returns what it got and callers fall back (the database). A failed subscribe must not leave a handler registered: the next subscribe would believe the channel is live and never receive anything. Pub/sub has its own connection, created on first subscribe, re-subscribed by ioredis after a reconnect (pinned), closed with the backend; messages sent while it is down are lost by contract. `Cluster` closes the bus before the backend, or registrations outlive the process until their TTL.
