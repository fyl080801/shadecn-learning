# REQ-GALSTORY GalStory 控制台：故事管理与模型配置

> 状态：**部分实现** —— 侧栏入口、三条路由、故事库 / 故事详情 / 模型配置三个页面、
> Node 侧反代与两个环境变量均已落地，**数据全部来自真的引擎**（`gal-story serve`）。
> 写操作与对局界面尚未做（见第 6 节）。
>
> 关联外部项目：[gal_story](../../gal-story)（Python，精简叙事引擎）。它的 HTTP 面见那边的
> `docs/reference/http_api.md`。**本需求为它补了两条作者面读口**（故事详情、模型配置），
> 其余一律用它已有的接口。

## 1. 目标

1. 在侧栏开一个 **GalStory** 分组，把这块功能与那串演示页分开 ——
   它是一整块功能（故事 + 配置，将来还有对局），平铺进去「这两项是一起的」就只能靠位置猜。
2. **故事管理**：列出作者态的故事模板，点进去看角色、编制、存档与装载期体检。
3. **模型配置**：看清「每个环节指到哪条连接、那条连接够不够用」，并给出体检结论。

### 1.1 为什么故事与存档不是同一张表的两个筛选项

引擎里最要紧的一条语义是：**开一局会把模板整份复制进存档**（`<save>/story/`），
此后改模板不影响进行中的那一局。把两者混进一张表，这条语义就被藏起来了。
所以故事库只列模板，存档挂在各自故事详情的一个页签里 ——
与 `Projects.vue` / `PersonalFlows.vue` 分成两页是同一条判据。

### 1.2 为什么配置页的主角是一张矩阵，而不是一堆表单

`config.yaml` 摊成表单是最容易做的样子，但那样等于把问题原样丢回给人。
真正的问题在于 `connection_id` 一个字段同时背着两件事：

- **这一步要什么** —— agent 固有（结构化产出 / 工具调用 / 该不该为思考付钱），换端点不变；
- **谁提供它** —— 端点属性，换端点全变。

引擎为此把 agent 划成三类（`creative_text` / `creative_structured` / `mechanical`），
让「按类绑定」这一层承担后者。控制台把这层结构画出来：
**按类分组的解析矩阵**，组头就是 `agent_bindings` 那三行（换 provider 时要动的就是它们），
组里每行显示这个环节最终解析到哪、**是从哪一层来的**、墙钟上界多少、体检有没有话说。

这类错配的共同点是**跑得起来**：只是每次多赔一趟往返，或者为拿不到的思考付钱
（实测输出 token 的 81% 是思考，而它走 `reasoning_content`，langchain 直接丢弃）。
看不出来，正是它值得画一张矩阵的理由。

## 2. 名词

| 名词 | 含义 |
|---|---|
| 故事 / Story | 作者态的模板目录：`story.yaml` + `characters/` + `knowledge/` |
| 存档 / Save | `<storage>/<story>/<save-id>/`，含模板的**冻结副本**与运行态 `state/` |
| 故事线 / Line | 存档里的一条分支（git 的 `line/*`）。回退恒开新线，原线一个字不动 |
| 场序 / sceneNo | 1-based、跨舞台连续。回退菜单与存档点用的就是它 |
| 环节 / Agent | `clients.get(名)` 的那个名，也是 `config.yaml agents[].name`，共 15 个 |
| 连接 / Connection | 一个模型端点：provider / model / base_url / 超时 / 三条能力声明 |
| 三类 / AgentKind | `creative_text`、`creative_structured`、`mechanical` |

## 3. 数据从哪来

浏览器**不直连引擎**。请求打到本应用的 `/api/galstory/*`，由 Node 反代到
`GAL_STORY_API_URL`（`server/routes/galstory.ts`）。三条理由：

1. 引擎那一侧**没有任何鉴权**、缺省只听 127.0.0.1（它自己的文档开头就写着「要对外就自己挡在
   反代加鉴权后面」）。挂在这里，`/api/*` 那道 `requireAuth` 就是那层鉴权；
2. 一个进程一个端口是本项目的既有形态，直连要多一套 CORS 与两个 origin；
3. 地址是环境变量，因此不进前端 bundle。

**反代只转发 GET。** 这不是随手加的保险，而是贴着引擎自己那条判据的：它把「要花钱 / 会写」
编码成了非 GET —— `POST …/open` 首次要跑建档（几十次模型调用）、`DELETE …?confirm=true`
会删掉玩家几十轮的实录、`POST …/rollback` 会换掉整个 `state/`。要接对局就在
`WRITE_ALLOW` 里逐条开，让「这条口会写数据」是一个看得见的决定。

两个环境变量（见 `.env.example`）：

| 变量 | 说明 |
|---|---|
| `GAL_STORY_API_URL` | 引擎地址，例如 `http://127.0.0.1:8000`。**空 = 不开这块功能**，页面显示「未配置」并说清该设哪个变量 —— 这个仓库里绝大多数人不跑那个引擎 |
| `GAL_STORY_API_TIMEOUT_MS` | 代理超时，缺省 30000。**必须自己给**：fetch 没有上界，卡住的上游会把请求永远挂着。⚠️ 30s 是按只读口给的，接对局时要调大 |

### 3.1 为引擎补的两条口

对着已有接口把界面接完之后，缺的正好是这一版界面的两块主体，故在引擎那边补上（都是**只读**）：

- `GET /api/stories/{name}` —— 作者面故事详情。选单那条口除 `title` 外一个字都不给
  （`StorySpec` 「仅导演可见」，里面有 `core_conflict`/`ending`），而详情页要的是角色、编制、
  节拍旋钮。**两条口是两条剧透判据，刻意不合并**；两条都不给 `ending`/`core_conflict`/`world`。
- `GET /api/config` —— 模型配置 + **绑定解析结果** + 体检。

同时在引擎里补了三样能力，都是为了**不让判据在前端重写一遍**：

| 补的东西 | 为什么 |
|---|---|
| `AgentClients.binding_of()` | 原来只有私有的 `_conn_id_of` 给结果，不给「这个值来自三层里的哪一层」。作者要回答的是「换 provider 时该改哪几行」，那取决于来源 —— 前端自己算就是同一个判据两处声明 |
| `AgentClients.time_budget_of()` | 单次调用的墙钟上界。结构化环节比同样配置的自由文本**多串一段纯文本兜底**，那个公式在引擎仓库里算错过一次，不该让前端再抄一遍 |
| `narrative.story.lint_story()` | 装载期那几条体检原来只落 `logger.warning`（淹在几千行日志里）。改成返回结构化 `StoryIssue`，`load_story` 仍照旧 log —— 装载期与接口从此同一个判据 |

顺带把体检级别的词表统一成 `error/warn/info`（`BindingIssue` 原来说 `warning`，
而 `knowledge.pages.LintIssue` 的 docstring 写着另一套 —— 同一件事两个词，在 API 上就是
让调用方自己去猜哪个口用哪种写法）。

## 4. 页面与路由

| 路径 | 页面 | 说明 |
|---|---|---|
| `/galstory` | — | 重定向到故事库，只兜住手输 |
| `/galstory/stories` | `views/galstory/Stories.vue` | 故事库：搜索 + 表格 + 体检计数 |
| `/galstory/stories/:storyId` | `views/galstory/StoryDetail.vue` | 概览 / 角色 / 编制 / 存档 / 体检 |
| `/galstory/config` | `views/galstory/ModelConfig.vue` | Agent 绑定 / 连接 / 采样预设 / 体检 |

侧栏两个入口（故事库、模型配置）；故事详情走 `NavItem.match: "prefix"`，
点进详情时侧栏的「故事库」继续亮着 —— 否则一进详情侧栏就整个失去当前位置。

## 5. 功能需求

### 5.1 故事库

- 按名称 / id 搜索。**在本地做**：故事是几个到几十个的量级，一个 `?keyword=` 参数换来的是
  引擎那一侧多一条要维护的判据，而它对结果没有任何影响。
- 每张卡给出：编制、角色数、存档数。**没有故事简介，那是刻意的**（选单口除 `title` 外一个字
  都不给，见 §3.1）；也没有「更新时间」—— 接口没有这个字段，与其拿目录 mtime 造一个语义可疑的
  数，不如不显示。
- 编制那一格：**没写 `stages:` 时显示「单场景」而不是「0 场」** —— 那类故事没有转场也就没有
  回退点，是玩法上的真实差别。

#### 5.1.1 版式：3:4 竖版封面的卡片栅格

一个故事是一件**作品**，不是一行记录 —— 故列表是卡片而不是表格，主视觉是封面
（`story.yaml` 的 `cover:`；作者没给、或外链挂了，都落占位 —— 判据在展示层，引擎只如实说
「给没给」，刻意不编一个默认地址）。

- **比例写死 3:4（竖版）**，不随图走：图是外链、尺寸各式各样，让它自己撑高度的话同一行的
  卡片会各长各的，栅格立刻变成参差不齐的瀑布流。`object-cover` 裁掉多余的。
- **列数**：`grid-cols-1 sm:grid-cols-2 lg:grid-cols-3 xl:grid-cols-4`。手机一列，往上逐档加。
  判据是**卡片别窄过 ~200px**（3:4 的封面再窄下去标题只剩两三个字，底下那行两颗按钮也开始
  互相挤），按侧栏展开 256px 算，最窄的两档是 xl 四列 ≈ 220px、lg 三列 ≈ 229px，都刚好在线上
  —— 判据不是「屏幕大就多塞几张」。
- **用 grid 不用 `flex-wrap`**：卡片必须等宽等高，而 `flex-wrap` 给不了 —— 要等宽就得手算
  `basis` 与 `gap` 的那笔账，最后一行还会被拉伸或留下参差的尾巴。
- **骨架屏与真列表共用同一串栅格类**（`Stories.vue` 的 `GRID_CLASS` 常量，唯一声明处）：
  抄两份就是同一个判据两处声明，而漂了不报错 —— 只是加载完那一瞬间整版跳一次。
- **四个动作分两处放**：主动作（新开始 / 读进度）在卡片底边等分一行，次要动作
  （编辑或复制 / 删除）压在封面右上角。⚠️ 这不是审美取舍：改版前是「一行一条」的横条，中间
  `min-w-0 flex-1` 的标题块、右边 `shrink-0` 的四个按钮，宽度不够时按钮一个像素都不让
  （`whitespace-nowrap`），于是**盖在**标题与 id 上（id 被切成三截），最右那颗删除还溢出卡片
  被裁掉一半 —— 而桌面上完全看不出来。次要动作也**不藏在 hover 里**：手机上没有 hover，
  藏起来等于在手机上删掉这两个功能。
- 状态徽章（不可开局 / 进行中）压在封面左下：扫一排封面时要一眼看见的就是这两条；
  「我的」跟着标题走（它是归属，不是状态）。
- **整张卡可点**（进详情页），故卡内每个按钮都要 `@click.stop` —— 漏一个，点「新开始」会
  顺带跳走。移到卡片里之后按钮的位置变了、这条判据一个字没变。

⚠️ **单列那一档的明码代价**：390px 宽的手机上一张卡约 600px 高，一屏只看得到一张半。
换成两列能翻一倍密度，但封面会窄到 ~160px —— 这一版选了「看清作品」而不是「一屏多塞几个」。

### 5.2 故事详情

五个页签对着故事目录的五样东西，**全部只读**（改故事是改磁盘上的 yaml，
在这里再做一份能改的表单就等于让同一件事有两个说法）：

- **概览** —— 玩家人设与展示层命名策略、知识三层的条目数、提交与压缩的节拍、
  角色间认知的节拍、输出核验开了哪几个。两条会静默出事的形态提到最上面：
  **缺 `public_ref`**（运行期降级成真名，「先有观察、后有名字」当场作废）与
  **永不落库**（单场景 + 没配 commit 阈值）。
- **角色** —— 表层卡、公共指代、私有条目数、作者态声明的相识关系。
- **编制** —— 舞台 → 场景。`goal` 与 `end_when` **并排放**：判定器只认后者而
  **导演读不到它**，收尾事件没同时写进 `goal` 就是死锁（判定器等着，导演不知道要排）。
- **存档** —— 进度、版本后端、建档时间，以及「此刻在不在引擎内存里跑着」。
  进度直接用引擎拼好的那句 `progress.label`（它**现读文件系统**），前端不自己再拼一遍。
  故事线不在这一页：那要按存档各发一条 `GET …/lines`，而单场景故事那条口会 409
  （「这个故事没有回退这回事」，不是错误）—— 它属于对局界面。
- **体检** —— 三级列表，严重的排前面。文案里的 `**…**` 是引擎写给日志看的重点标记，
  这里切段渲染成加粗（**不走 `v-html`**：哪怕后端是本机引擎，把它的字符串当 HTML 插进 DOM
  也是一条不该开的口子）。

### 5.3 模型配置

- **Agent 绑定**（缺省页签）：三张卡片就是 `agent_bindings` 的三行 + 一张解析矩阵。
  点任意一行打开详情，把**三层优先级**画出来（哪一层写了、哪一层赢了），
  并给出这一步的墙钟上界 —— 结构化环节比同样配置的自由文本**多串一段纯文本兜底**，
  这笔账算错一次就会把「放宽窗口、收窄预算」算成了放宽两次。
- **连接**：卡片，每张带三条能力轴的徽章（结构化 / 工具调用 / 推理）+ 流式。
  三条轴互不相通，不合并成一个「支不支持」。还显示「几个环节解析到它」。
- **采样预设**：连接管「谁提供、卡多久算卡住」，预设管「怎么采样」，两件事分开列。
- **体检**：行上的 + 不挂在行上的，一起列。

### 5.4 体检

**判据全在引擎里，前端只渲染。** 曾经有一版在 `src/lib/galstory.ts` 里自己实现了三层优先级
与几条体检规则并配了 13 条用例 —— 那是错的：`AgentClients.binding_of` 的 docstring 明写着
「在调用方重写一遍就等于让同一个判据有两处声明，迟早漂」，而漂了不报错，只是矩阵上显示的
绑定与引擎实际打过去的那条不是同一个。接上真接口时那一版被整个删掉。

前端只多做一件引擎没做的判断：**`binding.resolved === false` 渲染成 error**。
引擎的 `lint_agent_bindings` 对这一档刻意 `continue`（连接压根不存在时交给运行期 `_build`
去 warning），但对着配置看的人来说「指到了一条不存在的连接」正是最该一眼看见的
—— 那一步的超时与预设会全丢，而且完全静默。`resolved` 这个字段就是为它补的。

## 7. 本期不做

- **写操作**。引擎那一侧就只有读口（故事与配置都是「改磁盘上的 yaml」），反代也只转发 GET。
  配置页的连接详情给出可贴回 `config.yaml` 的片段，而**不放一个点了没反应的「保存」按钮**
  —— 那比没有按钮更糟；页头直接把配置文件的绝对路径显示出来。
- **对局界面**（开一局、读档、回退、AG-UI 事件流）。那是下一块，接的时候要动三处：
  反代的 `WRITE_ALLOW`、`GAL_STORY_API_TIMEOUT_MS`（建档几十秒到几分钟），
  以及 SSE —— 反代现在是「读完再转发」，事件流要改成流式透传。
- **跨故事的「全部存档」列表**。存档总归属于某个故事，从故事进去与领域一致；
  真要它，再单开一页，不塞进故事库的页签。
- **故事编辑**。作者手上那份 yaml 带着注释、还在 git 里。

## 8. 待确认

1. **作者面接口没有鉴权边界**。引擎整个服务都没有鉴权，`GET /api/stories/{name}` 与
   `GET /api/config` 对玩家全是剧透。今天靠**调用方自己分清**（本应用的 `/api/*` 要登录，
   且只有作者面在用）。将来真要把对局界面开给别人，要挡的就是这一族口。
2. **`src/types/galstory.ts` 是引擎视图模型的镜像**，两边是两个工程，**改一边要同步另一边**
   （同 `src/types/flow.ts` ↔ `server/store/flow-types.ts`）。`src/lib/galstory-agents.ts`
   现在只剩中文显示名（纯展示）；判据那部分已经随接口下发了。
3. **反代是「读完再转发」**，对 JSON 读口没问题，但 AG-UI 那条是 SSE —— 接对局时必须改成
   流式透传，否则整轮演完才出第一个字。
