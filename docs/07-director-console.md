# REQ-DIRECTOR 3D 导演台（视口）

> 原「3D 导演台」是带角色、时间轴、面板、顶栏、工具栏的完整页面（`/3d-scene`），已**下线**。现在只保留它的**视口渲染与视口内交互**，单独成页 `/3d-viewport`。需求编号保持不变，内容按现状重写；没有迁移的部分列在 §5。
>
> §1–§4 是现状。**§7 是下一阶段的规划**（规划中）：场景和时间轴存进画布节点、多人协同、agent 用导演台工具摆场景和编排动画，经渲染服务出图（§7.9）。

## 1. 目标

在 3D 视口中摆放对象与**机位**、预览机位取景，为内容拍摄前的场景调度与运镜预演提供视口层。底座是 [REQ-3DEDITOR](06-three-editor.md) 的渲染核心（`ThreeEditor` 上下文 + `EditorViewport`），业务叠加层在 `@/components/director`。

页面：`/3d-viewport`（`views/three/Viewport3D.vue`，路由名 `Viewport3D`，标题「3D 视口」，**不进侧栏菜单**，路由清单见 [REQ-SHELL](01-app-shell.md)）。

## 2. 页面

- 整屏只有 3D 视口，没有顶栏、工具栏、面板、时间轴。
- 编辑器实例用 `createEditor("3d-viewport")` 创建，随页面创建、随页面卸载销毁。
- **不做持久化**：每次打开都是同一份默认场景。
- 默认场景：立方体、球体、圆锥各一，以及一个只显示视锥线框的机位（源项目的机位实体模型来自后端资源索引，本仓库没有）。
- 默认画幅 16:9（页面没有工具栏可切换，所以一进来取景框就生效）。

### 2.1 画布导演台节点里打开

- 画布上导演台节点的「打开导演台」按钮：点了**全屏**打开导演台，盖住整张画布；左上角返回画布（Esc 同样关闭）。开着的节点被删掉（撤销、协作者删除）时自动关闭。
- 和 `/3d-viewport` 用**同一套渲染组件**（`ThreeEditor` + `EditorViewport`），但**不放默认场景**：视口里是节点 `data` 里的 `dc.*` 场景（§7.2）的投影。
  **取景框（画幅叠加层）本期不显示**；`dc.aspect` 照样存、照样给 agent 测量用。
- **最小编辑界面**（§7.6），和画布同一套设计语言：视口占满整屏，控件都是浮在上面的胶囊 / 圆钮。
  - 左上一枚胶囊，**只有两样**：返回画布的图标 + 导演台节点的名字（不可在这里改名）。
  - 右上：对话按钮（和画布右上角同一个组件，§7.5）。
  - 左下视图控件（同画布左下角的胶囊）：重置视角、视角罗盘开关。罗盘默认不显示，打开后在按钮上方（同画布的小地图）；机位视角下罗盘不显示。
  - 底部正中圆角工具栏（同画布底部工具栏）：移动 / 旋转 / 缩放切换 ｜ 「添加」菜单（立方体 / 球体 / 圆锥 / 圆柱 / 平面 / 机位 / 灯光）、删除、选中机位时「设为当前机位」
    ｜ 导演台撤销 / 重做 ｜ 时间轴开关。工具栏右边挂快捷会话的流光圆钮（同画布，§7.5）。
  - 时间轴默认收起，点工具栏上的开关贴底展开 / 收起。
  - 有 agent 占用本节点时，顶部正中一行「某某的助手正在编辑这个场景」（§7.5）。
  - 点选对象出 Gizmo。
- **层级**：关着时不在页面上，不挡画布任何操作；开着时浮在画布之上（不跟画布缩放），指针、滚轮、快捷键都只作用于导演台 —— 在导演台里按 Delete / Ctrl+Z 不会删掉、撤销画布上的东西；仍在对话框、提示之下（连接被终结的对话框照样能盖住它）。
- **数据在节点里**（§7.2）：打开时读、编辑时写导演台节点的 `data`，随画布协同、落库；刷新、关掉再打开都在。

## 3. 功能需求

### 3.1 选择与变换

- 视口内点选对象，选中后显示变换 Gizmo（`DirectorTransformControls` 提供移动 / 旋转 / 缩放切换），Gizmo 形态跟随当前模式。
- 选区与 Gizmo 归属是模块级单例；页面进入时必须复位，否则上一次停留对象的 uuid 会让新场景里的 Gizmo 不出现。
- Delete 键删除选中对象。
- 保留视角小工具（`DirectorViewHelper`：轴向罗盘 + 重置视角）。
- 视口点击空白取消选中。

### 3.2 机位

- 机位是 `userData.isDirectorShot` 的透视相机。
- 选中机位时绘制视锥，并在地面上投出视锥覆盖范围（footprint）。
- 机位支持注视目标 / 注视坐标（`useCameraLookAt`，持续跟随），以及注视装置（`useDirectorCameraRig`）。
- 机位正作为视口相机时，它自己的机位模型必须隐藏（`useCameraModelVisibility`）。
- 视口相机控制（`useDirectorCameraControls`）负责导演视角与机位视角下的操控。

### 3.3 取景框

- 按当前画幅比例（`21:9 / 16:9 / 4:3 / 1:1 / 3:4 / 9:16`，`auto` 表示不显示）在视口中画出取景框，框外区域做模糊 / 压暗。
- 必须是**纯 CSS 叠加层**（`DirectorAspectRatioOverlay`），不参与 Three.js 视口渲染 —— 不进入截图 / 出图结果，也不影响渲染性能。

### 3.4 其它视口行为

- 图形统一使用 `useDirectorShapeMaterial` 的表面材质，保证任意灯光下轮廓清晰。
- 全景背景（天空球）属于 `editor.backdrop` 而非 `editor.scene`（`useDirectorSceneBackdrop`）。

## 7. 下一阶段：场景与时间轴进节点、agent 编排（规划中）

### 7.1 目标

导演台节点里的内容是一个**可播放的 3D 场景**：

- 人可以手动添加图形（几何体、模型、机位、灯光），摆放、旋转、缩放；
- 有一条时间轴，图形随时间移动、缩放、旋转，可以播放、拖动时间；
- agent 能用导演台工具搭场景、编排动画。agent 写入的过程在导演台里实时可见，在对话里也能看到每一步；agent 能精确测量尺寸和位置，
  也能经渲染服务出图来看结果。渲染服务和视口用同一个渲染库，见 §7.9；
- 运镜能在视口里预览，也能由服务端逐帧渲染成视频，从导演台的输出端口交给下游（§7.9.4）；
- 多人同时打开同一个导演台，看到的是同一份场景，各自的改动实时同步。

### 7.2 数据：存进画布的 Y.Doc

**结论：场景和时间轴都存在导演台节点的 `data` 里，按 [REQ-CANVAS](13-flow-canvas-management.md) §3.7.1 的平铺分键存。**
Y.Doc 是唯一的事实源，视口里的 three.js 场景只是它的投影（和画布节点由 store 投影出来是同一个关系）。

理由：协同、落库、断网缓存、撤销、agent 写入（`flow-ops`）、agent 感知别人的改动（[REQ-AGENT](20-agent-canvas.md) §3.10.2）这些链路都能直接复用；
导演台的产出（截图、录制）本来就要经 `runtime.outputs` 流到下游节点。另起一个房间或一套持久化，要把这些都重做一遍。

**键与值**（值都是普通 JSON；前缀之间不嵌套）：

```
dc.duration     number   时长，毫秒；显式设定，默认 5000；打的关键帧超出时长时自动延长到那一帧；播放默认循环
dc.fps          number   播放与吸附用的帧率，默认 30
dc.aspect       string   画幅（§3.3 的取值）
dc.activeShot   string?  当前机位的对象 id

dc.obj.<id>     { kind, name, parentId?（预留，本期不支持嵌套）, position, rotation, scale, geometry?, material?, assetUrl?, bounds?, camera?, light? }
                kind: 'box' | 'sphere' | 'cone' | 'cylinder' | 'plane' | 'camera' | 'light'（'model' 预留，本期不做）
                单位：米；原点在几何中心；position / scale: [x, y, z]；rotation: 欧拉角 [x, y, z]，弧度，顺序 XYZ
                geometry：参数化尺寸，如 box { width, height, depth }、sphere { radius }、cone / cylinder { radius, height }
                assetUrl：model 的 glb 地址（对象存储，见 REQ-CANVAS「资源上传」），二进制不进 doc
                bounds：model 的本地包围盒 { min, max }（§7.3.2），尺寸测量靠它
                camera：{ fov, near, far }；light：{ type, intensity, color }
dc.track.<id>   { objectId, property, interp }
                property: 'position' | 'rotation' | 'scale'，以及机位的 'fov'；interp: 'linear' | 'step' | 'smooth'
dc.kf.<id>      { trackId, t, value }
                t：毫秒整数；value 与 property 同形
```

- **关键帧各占一个键**，不放进轨道里：agent 改一条轨道的同时，有人在拖同一条轨道上的另一帧，两边都要留下来。
- 旋转按欧拉角存，方便人读、方便 agent 写；插值时转成四元数沿最短弧做球面插值，所以**相邻两帧的转角必须小于 180°**
  （`set_keyframes` 超过时给警告；运动预设 `turn` 每 90°、`orbit` 每 15° 打一帧，转几圈都成立）。
- `smooth` 是每一段做 smoothstep，不是三次样条。
- 约定与 three.js 一致：几何体以中心为原点、高沿 Y；`plane` 水平铺在 XZ 面、法线朝 +Y、没有厚度（前端用 `PlaneGeometry(w, d).rotateX(-π/2)`）；
  `cylinder` 上下同径；机位朝本地 -Z，fov 是竖直方向、**以度存储**（同 three，不换成弧度）。
- 测量时 `auto` 画幅按 16:9 算；时长不能设得比最后一个关键帧短。
- id 由 `createId()` 生成，不用下标；前缀和 id 规则遵守 §3.7.1 的三条硬规则。
- `flow-collection.ts`（`collectionKey` / `readCollection` / `spreadCollection`）挪到 `packages/shared`，并新增 `director-doc`：键前缀、校验、上限。
  导演台的写操作放进 `@shadecn/shared/flow-ops`（与 §7.3.1 的原子操作一一对应），编辑器和 agent 都只走这一套。

**不进 Y.Doc 的：**

| 状态 | 放在哪 |
|---|---|
| 播放头位置、播放中 / 暂停 | 本地，每个人各自播放 |
| 选中的对象 | awareness（同协同画布的选区规则） |
| Gizmo 拖动、时间轴上拖关键帧的中间值 | 本地草稿，松手提交一次（REQ-CANVAS §3.7.2） |
| 视口相机（导演视角） | 本地 |

**上限**（暂定，`director-doc` 里一份常量，编辑器和 agent 同一份）：每个节点对象 ≤ 200、轨道 ≤ 400、关键帧 ≤ 2000；
单个事务（含脚本的一次批量执行）序列化后 ≤ 512 KB（单条协同消息上限 1 MB）。
**关键帧必须稀疏**：agent 按帧烘焙（30fps × 10s × 每个对象 3 条轨）会立刻超限，提示词与工具校验都要挡住，`animate_motion` 生成的帧数也有上限。
上限还要对着 `Flow.graph` 投影的 2 MB（`GRAPH_LIMITS.bytes`）实测一次（§3.7.1 末尾提过还没量）；必要时投影里去掉 `dc.*` —— 列表计数用不到它们。

**规划中：背景与贴图进 doc**（§7.9 的 P6）。视口现在的天空色、全景贴图是编辑器的本地状态，渲染服务拿不到。
为了让服务端渲染和人看到的一致，以后加进 doc：

```
dc.backdrop     { skyColor, panoramaUrl?, panoramaRadius?, environment: 'room' | 'panorama' }
                panoramaUrl：对象存储里的素材地址；二进制不进 doc
dc.obj.<id>     material 增加贴图字段（如 map），值是对象存储的素材地址
```

没进 doc 之前，渲染服务一律按默认背景（默认天空色 + Room 环境光）出图，并在结果里写明「背景为默认」。

### 7.3 agent：导演台技能

工具按内置技能组织（[REQ-AGENT-SKILL](23-agent-skills.md)）。导演台相关的技能有三个：`director`（写 + 量）、`director-view`（看）、`director-script`（批量生成，后期）。
消息里提及了导演台节点时前两个自动加载（从导演台里发起的新会话自动带上这个节点的提及，§7.4）；否则由模型按需加载。

**不让模型直接写场景 JSON。** 整块写 JSON 有三个问题：id 和引用会写错；角度、插值这类数学会算错；一次写几百 KB，
错了只能整体重来，模型中途也拿不到任何反馈。所以 agent 和场景之间是一个**写 → 量 → 看**的闭环：

| 层 | 做什么 | 依据 |
|---|---|---|
| 写（§7.3.1） | 原子操作：每次改一小块，参数短、校验严，相对位置由服务端算 | 工具返回写入后的实际数值 |
| 量（§7.3.2） | 解析计算：包围盒、距离、穿插、机位取景 | **尺寸和位置以这一层为准** |
| 看（§7.3.3） | 渲染出图交给多模态模型 | 只判断观感（构图、比例协调、动作是否自然），不从图上估尺寸 |

#### 7.3.1 原子操作（写）

| 工具 | 做什么 |
|---|---|
| `get_director_scene` | 读场景：对象、轨道、关键帧（可只读部分 id） |
| `add_objects` | 新建若干图形 / 模型 / 机位 / 灯光：种类、名字、几何尺寸、位置、朝向、颜色；返回 id |
| `transform_objects` | 改位置 / 旋转 / 缩放：绝对值（`set`），或相对当前值（`by`：平移若干米、绕某轴转若干度） |
| `place_object` | 约束式摆放，由服务端按包围盒算坐标：落到地面、放到另一个对象顶上、贴在另一个对象某一侧并留出间距、放到某个坐标 |
| `align_objects` / `distribute_objects` | 按某轴对齐（最小、中心、最大）/ 等距排开 |
| `aim_camera` | 机位朝向某个对象或坐标；或给定一组对象，按 fov 和画幅算出刚好装下它们的距离（可留边距） |
| `update_objects` | 改名字、颜色、材质、几何尺寸、相机 fov、灯光参数 |
| `set_director_settings` | 改时长、帧率、画幅、当前机位 |
| `set_keyframes` | 在某个对象某个属性上增改关键帧（显式给时间和值；轨道不存在时一起建） |
| `animate_motion` | 运动预设，由服务端生成**稀疏**关键帧：`orbit`（绕目标转，半径、角度范围）、`move_along`（经过若干点）、`turn`（转若干度）、`scale_to`；都带时长与缓动 |
| `delete_director_elements` | 删对象（连带它的轨道和关键帧）、轨道或关键帧；计入每轮删除预算 |

共同规则：

- **面向模型的单位是米、度、秒**，存储时由工具换成弧度、毫秒（§7.2）。模型不用碰弧度和毫秒，也就不会在这里出错。
- 参数用严格的 schema（枚举、数值范围、数组长度），由 pi 先校验一次，服务端按 `director-doc` 再校验一次。批量参数每次最多 20 项，有一项不合格就整个拒绝，不部分写入。
- 每次调用一个事务，经 `@shadecn/shared/flow-ops` 的导演台操作写入；agent 和编辑器只有这一条写入路径。
- **返回写入后的结果**：受影响对象的世界坐标包围盒、尺寸和中心；动画类工具返回生成了几帧、起止时间。模型不用再读一遍就知道自己写成了什么样。
- 引用只认 id。工具报「不存在」时模型要重新读，不能猜（同画布工具的规则）。

#### 7.3.2 测量（量）

| 工具 | 返回 |
|---|---|
| `measure_objects` | 若干对象在时刻 `t`（缺省 0）的世界包围盒、长宽高、中心、底面高度 |
| `measure_distance` | 两个对象之间的中心距离、各轴间隙、包围盒表面间距（重叠时为负） |
| `check_scene` | 在时刻 `t` 或若干采样时刻检查：互相穿插、低于地面、悬空、超出机位画面的对象 |
| `camera_view` | 某个机位在时刻 `t` 的取景：每个对象是否在画面里、在取景框中的位置和占比（取景框坐标 0–1） |

- **在服务端解析计算，不渲染**：时刻 `t` 的状态按关键帧插值得出；几何体的尺寸来自参数（精确），模型的尺寸来自 `bounds`。
- 插值与几何计算放在 `@shadecn/shared/director-eval`，**前端播放和服务端测量用同一份代码**，所以量出来的就是人播放时看到的那一帧。
  不碰 DOM（shared 的规则）；矩阵与四元数可以直接用 three 的数学模块，实现时定。
- **精度如实说明**：几何体是精确值；模型和旋转过的对象用的是包围盒（偏保守）；没有 `bounds` 的模型返回「尺寸未知」，不猜。
  遮挡只按包围盒近似判断，并在结果里注明。
- **模型的 `bounds`**：上传 glb 时由服务端读 glTF 里各网格 `POSITION` accessor 的 `min` / `max`，结合节点变换算出来（不用加载整个模型）；
  解析失败时前端加载完模型后补记一次（同图片节点记录宽高：不进撤销栈，值没变不重复写）。
- 测量工具只读（`flow:read`），不计入写入预算。

#### 7.3.3 渲染（看）

| 工具 | 返回 |
|---|---|
| `render_view` | 某个导演台在某个视角的一张图。可以是一个时刻，也可以是最多 6 个时刻拼成的一张联系表（每格标时间），用来检查动画和运镜 |

视角 `view` 可选：

| 取值 | 含义 |
|---|---|
| 机位 id | 从这个机位看，画幅取 `dc.aspect` |
| `top` / `front` / `side` | 正交方向的总览，距离按场景包围盒算出，刚好装下所有对象 |
| `overview` | 斜上方的总览视角，同样按包围盒算。服务端不知道人在视口里的视角，所以没有「导演视角」这一项 |
| `user` | 发这条消息的人当时在视口里看到的视角与时刻，取自消息上下文（§7.5）。消息不是从导演台里发的，就没有这一项 |

- **标注模式**（`annotate`，默认开）：在图上叠对象名称、地面米格刻度，机位视角再叠取景框。这样模型能把图上看到的东西和 id、测量结果对上。
- **渲染路径**：网关读出快照，交给独立部署的渲染服务；渲染服务在无头 Chromium 里打开专用渲染页，用和视口**同一个渲染库**画图（§7.9）。
  不用 Node 端的 headless-gl，也不用 Blender 之类的外部渲染器：那是另一条渲染路径，画出来的和人看到的不一致，看图就失去了意义。
- **快照语义**：渲染的是工具调用那一刻的快照，和测量一样。渲染期间别人改了场景，这张图就是旧的；结果里写明渲染的时刻、视角、对象数和跳过的元素。
- **图片走现有的看图通道**（[REQ-AGENT](20-agent-canvas.md) §3.10.7）：`render_view` 和 `view_node_media` 一样是网关工具。图只往下游送给模型；对话记录、补发、前端里换成一句占位；
  和 `view_node_media` 共用每轮的图片字节预算；单张图的分辨率有上限（暂定长边 1024）。
- **技能 `director-view` 的可用条件**：配了渲染服务（`DIRECTOR_RENDER_URL`），并且模型支持图片输入。**不需要 `sandbox:exec`**，渲染不在沙箱里做。
  不满足时不提供，agent 只靠 §7.3.2 的测量工作，系统提示里写明「看不到画面」。
- 安全要求、渲染服务和渲染库的结构见 §7.9。

#### 7.3.4 脚本（批量生成，后期）

技能 `director-script`（需要 `sandbox:exec`，按需加载；本地 `process` 驱动下脚本直接跑在宿主机上，开启方式见 [REQ-AGENT-SKILL](23-agent-skills.md) §8 第 5 条）提供 `run_scene_script`，用于原子操作写起来太啰嗦的程序化内容，比如上百个对象的阵列。

- 脚本不输出场景 JSON，而是调用沙箱里预置的**导演台 SDK**（`addObjects`、`place`、`animateOrbit` 等）。SDK 的每个调用就是 §7.3.1 的一个原子操作，
  脚本跑完得到一份**操作列表**。runner 把它交给网关，网关逐条按原子操作的规则校验后，在一个事务里执行，一步就能撤回。
  所以整个系统只有一套写入词汇，脚本只是批量产生这些调用。
- **安全**：LLM 写的 JS 是任意代码，而 runner 进程的内存里有这一轮的 run token，两者在同一个容器、同一个用户下。所以：
  - 脚本用 Node 的权限模型运行：`node --permission --allow-fs-read=<脚本与 SDK 目录> --allow-fs-write=<输出目录>`，禁止子进程、worker 和原生模块，读不到 `/proc/<runner pid>/` 下的内存与环境变量；
  - 有超时（暂定 30s）、`--max-old-space-size` 和输出大小上限，被中止时随这一轮 SIGKILL（同媒体工具）；
  - 操作列表当不可信数据处理：总条数有上限，任何一条不合格就整体拒绝。

#### 7.3.5 工作方式（写进技能提示段）

1. 先 `get_director_scene` 了解现状，再用原子操作搭建，每一步看返回的数值。
2. 摆完一批用 `check_scene` 查穿插和悬空，用 `camera_view` 查机位取景，按数值修正。
3. 有 `director-view` 时，在关键时刻 `render_view` 看一眼观感；动画用联系表看几个关键时刻。
4. 尺寸、距离、是否穿插以测量为准，不从图上估。
5. 动画只打关键帧，不逐帧烘焙。

**分期**：先做写 + 量（`director`：全是网关工具，不需要 `sandbox:exec` 和渲染服务，任何部署都能用，本地开发也不会在宿主机上执行模型写的代码）；再做看（`director-view` 与渲染服务）；最后做脚本（`director-script`）。

### 7.4 导演台里的会话：全局 agent + 自动提及

> 原方案「节点范围会话」（会话绑定这个节点、画布只读、导演台工具只能改绑定的节点）**取消**，
> 改为所有会话都是全局 agent，靠提及指定节点（[REQ-AGENT](20-agent-canvas.md) §3.10.9）。

- **打开导演台算选中这个导演台节点**（只有它一个）：导演台里对话框的「新会话」、快捷会话，输入框开头自动带上这个节点的提及（可以删掉）；
  导演台节点底部输入框回车发出的消息，开头也补上它的提及（已经提及了就不重复）。
- 提及了导演台节点，这一轮自动加载 `director`（及可用时的 `director-view`）技能；画布工具（`canvas`）照常全部提供。
  agent 自己决定改哪些节点：可以改这个导演台，也可以加画布节点、连线、改别的导演台，都按 [REQ-AGENT](20-agent-canvas.md) §3.10.8 占用。
- 会话的 `nodeId` 只记入口：从导演台里发起的会话记下这个节点，用于在导演台里默认打开「我在这个节点上最近的会话」；它不限制工具、不影响占用。
- 它就是一个普通会话：进任务列表、对话里可见、可以停止，每轮的各项上限、授权和撤回规则都和其它会话一样（[REQ-AGENT](20-agent-canvas.md) §3.10.3）。

**父子 agent**：任务分解与并行的工程化手段，不做层级或占用隔离，见 [REQ-AGENT](20-agent-canvas.md) §3.10.11。
例如主 agent 把「给这三个导演台各搭一个场景」拆成三个子任务并行；子 run 同样是全局 agent，生成一张图连到导演台这类跨节点的操作照常可做。

### 7.5 界面：agent 执行过程的反馈

- **对话里**：工具调用照常显示，结果显示摘要（如「新建 3 个对象」「机位1 看得到 10 个，椅子2 与桌子1 穿插 4cm」）。
  `render_view` 的图在对话里显示为缩略图，点开看大图（图片本身不进对话记录，这里显示的是渲染服务另存的预览，见 §7.8）。
  `run_scene_script` 的代码默认折叠，可以展开。
  点工具调用定位到元素：导演台里的元素用 `<nodeId>/<元素键>` 表示（[REQ-AGENT](20-agent-canvas.md) §3.4.1），先打开那个导演台，再高亮对象。
- **视口里**：agent 的写入经 Y.Doc 到达，视口实时出现变化；刚被写过的对象短暂高亮（约 1.5 秒的包围框）。
  **分不清改动来自 agent 还是同伴**（doc 只告诉我们「远端来的」），所以近似成：**有 agent 占用本节点时，远端改过的对象**都高亮。
  全屏层顶部显示「某某的助手正在编辑这个场景」（自己的显示「我的助手」），来源是任务列表（`AgentRunEntry`）上的 `occupies`
  （[REQ-AGENT](20-agent-canvas.md) §3.4、§3.10.8）：哪一轮占用了这个节点就显示谁，多轮都占不了同一个节点。
- **对话入口**：全屏层盖住了画布右上角的对话入口，所以导演台里有自己的一套：右上角对话按钮 + 底部工具栏右边的快捷会话圆钮，
  **和画布上的是同一组组件、同样的对话逻辑**（对话 / 历史会话 / 进行中的任务三个视图，快捷会话开新会话执行），收起不断流、不丢草稿；
  文案换成「导演台助手」。它是**另一份**对话状态，和画布右上角那份互不影响（切会话不会把画布对话框也切走）。
  默认打开**我在这个节点上最近的那个会话**（会话列表里自己的、`nodeId` 是这个节点的，按更新时间取最新）；没有就是新会话，
  输入框开头带着这个节点的提及（§7.4）。新会话的第一条消息发出去时带 `nodeId`，只记入口；续聊不带。对话框里「新会话」、快捷会话开的新会话同样带上提及和 `nodeId`。
- **消息带上视口状态**（规划中，§7.9 的 P4）：从导演台里发出的消息，附带发送那一刻的视口相机（位置、朝向、fov）和播放头时刻，
  `render_view` 的 `view: 'user'` 用它渲染「我现在看到的画面」。只取发送那一刻的值，不实时跟随，所以模型看到的就是人发消息时看到的。
- **节点底部输入框**：导演台节点的输入框回车 → 打开全屏导演台，并在上面那个会话里发出这条消息，开头补上这个节点的提及（能力 `director-chat` 把 `composer:submit` 转成带 `prompt` 的 `director:open`）。
  那个会话正有一轮在跑时不发，放进对话框输入框并提示；发送被拒（如服务端没配模型）时同样放回输入框。已经开着同一个导演台时只发消息、不重新打开。
- **画布上**：节点上显示 agent 标签（同 REQ-AGENT §3.4）。

### 7.6 前端要点

- **投影**：一个「Y.Doc → three 场景」的对账器，按对象 id 增量创建、更新、删除 `Object3D`；只比较对象**除变换以外**的部分（种类、名字、几何、材质、机位 / 灯光参数），
  没变的对象保持同一个 `Object3D`（选区、Gizmo 挂在它上面），种类变了才重建。位置 / 旋转 / 缩放 / fov 一律由下面的求值写。
  机位没有实体模型，挂一个小机身当抓手（点它选中机位，机位视角下隐藏）；灯光挂一个小球当抓手。
- **写入**：人在视口里的编辑（Gizmo、添加 / 删除图形、打关键帧、删关键帧、设为当前机位）一律经 store 调 `@shadecn/shared/flow-ops` 的导演台 ops 写 `data`。
  three-editor 自带的 `Command` / `History` **不再作为数据源**（引擎在 Gizmo 松手时照样往它的 history 里记一条，没人读它）。
  **Gizmo 拖动是本地草稿，松手提交一次**（一个事务、一条撤销记录）；拖动中途数据变了（别人改了）也不打断拖动。
  **属性上有关键帧时**，静态值播放时看不见，所以这次拖动写成**播放头处的关键帧**（同一时刻已有就覆盖），并提示一句「…有关键帧：这次拖动记成了 Xs 处的关键帧」；
  没有关键帧的属性写静态值。
- **撤销**：导演台的编辑用**单独的 origin**（`DIRECTOR_ORIGIN`）：打开导演台时为这个节点建一个只跟踪它的撤销栈（作用域是这个节点），关闭时销毁；
  画布的撤销栈只跟踪画布自己的 origin，不跟踪它。导演台里的 Ctrl+Z / Ctrl+Shift+Z / Ctrl+Y 只作用于导演台的撤销栈；关掉导演台后，画布上的 Ctrl+Z 撤不到导演台里的改动，
  再打开导演台撤销栈是空的。广播、落库不看 origin，照常。
- **键盘**：开着时画布的快捷键一律不生效（不靠拦截按键传播，那样全屏层里的输入框、下拉菜单也收不到）。导演台自己的：Delete / Backspace 删选中的关键帧（没选关键帧就删选中的对象）、
  Ctrl+Z 撤销、Ctrl+Shift+Z / Ctrl+Y 重做、空格播放 / 暂停（焦点在按钮上时空格是按那个按钮）。焦点在输入框里时都不触发。
  **Esc**：在输入框里 = 让输入框失焦（不关导演台，里面的字不丢；再按一次才关）；在下拉菜单 / 对话框里 = 关那个菜单；其余 = 关闭导演台。
- **选区只在本地**：本期不进 awareness（§7.2 的表格写的是进 awareness，留到以后），别人看不到我选中了什么。
- **播放**：**不用 `AnimationMixer`**。每一帧调用 `@shadecn/shared/director-eval` 的 `objectStateAt`（时间线先 `compileDirectorTimeline` 编译一次，数据变了再重编），
  把结果写到投影出来的对象上。这一份插值就是「时刻 t 的场景」的唯一定义，服务端测量也用它；three 的 `InterpolateSmooth` 是三次样条，和这里按段 smoothstep 的 `smooth` 不同，用 mixer 播放会和测量对不上。
  播放中、拖播放头都不写 doc：播放头只改投影出来的对象，不改 `dc.obj.*` 里存的值。播放头、播放 / 暂停、循环（默认开）都是本地的；拖播放头吸附到帧。
- **界面**：**只补最小的一套**：添加图形菜单、选中 + Gizmo、Delete、时间轴（按对象列出轨道与关键帧、标尺、播放头、播放 / 暂停、循环），
  在当前播放头位置给选中的对象打关键帧（位置、旋转、缩放，机位再加 fov；值取这一时刻求出来的状态）；点关键帧选中它（播放头跳过去），Delete 删它。
  属性面板、复制粘贴、关键帧拖动、曲线编辑、机位视角切换都不做；复杂的编排交给 agent。
- **输出端口**（`image` 截图 / `video` 录制）本期不做：两者都由渲染服务在服务端产出（§7.9.4），不依赖有人开着浏览器。
- **渲染代码的归属**（规划中，§7.9.1）：对账器、图形材质、环境光与背景、渲染器设置都要搬进共享渲染库 `@shadecn/three-render`，
  视口和渲染页都从它导入，任何一边都不能另写一份。

### 7.7 验收标准

- [ ] 两个人打开同一个导演台：一人添加图形，另一人 1 秒内看到；两人同时改不同的对象、同一条轨道上不同的关键帧，都保留。
- [ ] 刷新、关掉再打开画布，场景和时间轴都在。
- [ ] 打关键帧后播放，对象按关键帧移动、缩放、旋转；拖播放头时对象跟着变；播放不产生任何 doc 写入。
- [ ] 在导演台里新开的会话（自动带着这个节点的提及）里让 agent「搭一个……的场景，镜头绕一圈」：对话里依次出现原子操作；视口里对象逐个出现；
  点工具调用能定位到对象。（撤回本轮依赖 [REQ-AGENT](20-agent-canvas.md) §3.5，那一项还没实现，实现后补这条验收。）
- [ ] 导演台里发起的会话：模型的工具列表里有 `director` 和全部画布工具；agent 改了这个导演台的场景时占用它，另一个会话的 agent 同时改它被拒并停下确认。
- [ ] 在导演台里 Ctrl+Z 只撤导演台里的改动；关掉导演台后，画布上的 Ctrl+Z 撤不到导演台里的改动。
- [ ] 导演台开着时按 Delete / Ctrl+Z 画布不变；对话面板的输入框能打字、回车发送；下拉菜单里按 Esc 只关菜单。
- [ ] Gizmo 拖一次只产生一次 doc 写入；有关键帧的属性拖完在播放头处多一个（或覆盖一个）关键帧，并有提示。
- [ ] 导演台节点底部输入框回车：打开导演台，消息发在这个节点最近的会话里、开头带着它的提及（新会话带 `nodeId`）；有 agent 占用本节点时顶部显示「某某的助手正在编辑这个场景」。
- [ ] `place_object` 把 0.5m 的立方体放到 0.8m 高的桌面上：`measure_objects` 量出立方体底面高度为 0.8m（误差 < 1mm），`check_scene` 不报穿插。
- [ ] 服务端测量的某一时刻位置，与前端播放到同一时刻时对象的位置一致。
- [ ] 配了渲染服务时：`render_view` 的图交给了模型，图上有对象名称与米格；对话记录与补发里没有图片字节。没配时工具列表里没有它。
- [ ] 同一个场景、同一个机位、同一个时刻：`render_view` 的图和视口切到该机位、拖到该时刻看到的画面，构图和明暗一致（并排对比，允许抗锯齿等细节差异）。
- [ ] 从导演台里发消息后 `render_view({ view: 'user' })`：图和发消息时视口里的画面一致。
- [ ] 渲染一次期间，渲染页除了自己的静态文件，没有发出任何网络请求（贴图上线后：只请求渲染服务自己的素材代理）。
- [ ] 贴图或背景引用了不属于本项目对象存储的地址：渲染服务不发请求，模型收到原因。
- [ ] （出片期）对一个 10 秒、30fps 的运镜出片：得到 300 帧的视频，任意一帧和视口拖到同一时刻的机位画面一致；出片中途取消，任务停止、不产生输出。
- [ ] （脚本期）脚本试图读 `/proc/1/environ`、起子进程、死循环：分别被拒、被拒、超时被杀，画布不变。
- [ ] 批量参数里有一项不合格、或超过对象 / 关键帧上限：整个调用被拒，画布不变，模型收到原因。

### 7.8 已定与待确认

已定（2026-10-29）：

- 关键帧属性：位置、旋转、缩放，以及机位的 fov。材质颜色、灯光强度以后再加，格式不用改。
- 本期不做模型（glb），只做几何体、机位、灯光；所以所有尺寸都能精确测量。
- 本期不支持对象嵌套，`parentId` 预留。
- 导演台有自己的撤销栈（§7.6）。
- 时长显式设定，默认 5 秒，关键帧超出时自动延长；播放默认循环。
- 上限先按 §7.2 的数值，实现后对着 `Flow.graph` 投影实测再调。
- 两个人同时改同一个对象只留一边，再加软提示。
- ~~节点范围会话里画布只读~~：节点范围会话取消，导演台里的会话是全局 agent，打开导演台即选中这个节点、新会话自动带上提及（§7.4）。
- 人在导演台里只做最小操作（§7.6）；输出端口本期不做。
- 取景框（画幅叠加层）本期不显示（2026-10-29）。
- 导演台里的选区本期只在本地，不进 awareness。
- 有关键帧的属性用 Gizmo 拖动 → 写成播放头处的关键帧（不写静态值），并提示（§7.6）。
- 「正在编辑这个场景」与高亮的来源是任务列表上的 `occupies`（节点占用，REQ-AGENT §3.10.8）；高亮分不清 agent 和同伴，按「有 agent 占用本节点时的远端改动」近似（§7.5）。
- `/3d-viewport` 不再跟进。

已定（2026-10-30，渲染方案）：

- 渲染用**共享的 three.js 渲染库 + 无头 Chromium**（§7.9）。不在每一轮的 agent 沙箱里渲染（每个沙箱都得按 Chromium 配资源，「看」也会被绑到 `sandbox:exec` 上），
  也不用 Blender 等外部渲染器（渲染路径不同，看到的和人看到的对不上；把 Blender 当编辑引擎还会多出一份事实源，回写 Y.Doc 有丢数据和覆盖并发编辑的问题）。
- 渲染服务**单独部署**，常驻工作池，集中限并发。
- 共享渲染库叫 `@shadecn/three-render`（`packages/three-render`），导演台专用的部分放在子路径 `@shadecn/three-render/director`。
- 背景和贴图以后要进 doc（§7.2 末尾），由同一个渲染库加载，视口和渲染服务的表现一致。
- 没有「导演视角」：总览视角按包围盒算（`overview`）；要看人当时看到的，就用消息附带的视口状态（`view: 'user'`）。
- 运镜出片由渲染服务离线逐帧渲染并编码，按 `t = i / fps` 步进，不是实时录屏。

待确认（第二、三期）：

1. 软件 WebGL（SwiftShader）的实测耗时：单帧目标 < 3s；联系表、连续帧（估算出片成本）、PMREM 预热和内存都要在 P0 里量。
2. `render_view` 的图另存一份低清预览给对话显示（存对象存储，对话里只记地址）—— 倾向要。
3. 机位「看得到」只按包围盒估计遮挡并注明；精确遮挡等渲染服务出来后看图判断。
4. 渲染服务控制浏览器用 `puppeteer-core` 还是 `playwright-core`：倾向 `puppeteer-core`，更轻，和 Chrome 官方的 headless-shell 配套更直接。

已知缺口（已实现部分）：

- 导演台工具的 `affectedIds` 只记 `<nodeId>/<键>`，没有再单独记节点 id；前端在画布上标 agent 时要从前缀里取节点 id。

### 7.9 渲染：共享渲染库与渲染服务（规划中）

> 方案已定（2026-10-30，§7.8），尚未实现。`render_view`（§7.3.3）、服务端产出的 `image` / `video` 输出端口（§7.6）都建在这一节上。

**原则：人看到的和服务端画出来的，是同一份代码画的。** 渲染页本身就是一个 Chromium，和人的浏览器只差在 GPU（真 GPU 对软件 WebGL）。
差别由渲染库统一封顶，不由两边各自处理。

```
agent runner ──/canvas/tool──▶ 网关 render_view（flow:read）
                                  │ canvas.read → readDirectorScene(dc.*) → 快照
                                  │ 宿主注入的渲染服务客户端
                                  ▼
                        渲染服务（单独部署）
                        Node + 无头 Chromium（SwiftShader）× N 个页面
                                  │ 把快照交给渲染页
                                  ▼
                        渲染页（静态产物，只从渲染服务自己加载）
                        import … from '@shadecn/three-render'
                                  ▲
前端视口 ──────────────────────────┘ 同一个包
```

#### 7.9.1 共享渲染库 `@shadecn/three-render`

- 位置 `packages/three-render`，**只在浏览器里用**，`three` 是 peerDependency。不放进 `@shadecn/shared`：shared 不准用 DOM，服务端也要打包它，
  而环境光（PMREM）、渲染器都离不开 WebGL。
- 分两层：
  - `@shadecn/three-render`：通用部分，包括渲染器设置、环境光与背景、素材加载接口、`whenReady()`、按时刻截帧。
  - `@shadecn/three-render/director`：导演台的部分，包括 dc.\* 的投影（§7.6 的对账 + 求值）、图形材质、从快照搭一个完整舞台（含按包围盒算总览视角）。
- 现在散在 `apps/web/src/components/director/` 里的这些都要搬进来：对账器、图形材质与表面参数、环境光与背景色、导演台的渲染器设置（tone mapping、阴影）、地面网格。
  跟编辑器相关的（Gizmo、选区、角色相关的旧代码）留在前端。
- **库要守住的约定**：
  - **求值只由传入的时刻 t 决定**：不用 `requestAnimationFrame` / `Clock` 推进时间，没有随机数，不用 `AnimationMixer`。逐帧出片和视口拖到同一时刻的画面才会一致。以后加任何会动的东西都要守这一条。
  - **素材加载由宿主注入**：`AssetResolver { load(url, signal) }`。视口走同源地址（带会话）；渲染页只请求渲染服务自己的素材代理。
    `colorSpace`、mipmap、各向异性、全景图转环境光、环境光强度都在库里统一设，两边不各自设。
  - **`whenReady()`**：素材全部加载完才返回。视口可以边加载边显示，渲染页必须等它之后再截图。
  - **统一的上限**：纹理最大边长、全景图尺寸、`pixelRatio`（渲染页固定 1）、抗锯齿方式都由库定。软件 WebGL 支持得更少，两边按同一套上限执行，画面才一致。

#### 7.9.2 渲染页

- 独立构建的静态页面，不挂在主应用上（主应用的页面都要登录，渲染页不能带会话、不能带 cookie）；不用 Vue。
- 对外只有一个入口：接收场景快照、视角、时刻（最多 6 个）、`annotate`、尺寸，返回 PNG。
  - 联系表：同一个舞台依次求值每个时刻，逐格画到一张图上，每格标时间。
  - 标注：WebGL 画完后叠一层 2D 画布，内容是对象名称（按对象中心投影到屏幕上）、地面米格刻度、机位视角下的取景框。镜像里要装 CJK 字体，否则中文对象名显示成方块。
- 快照在渲染页里再按 `readDirectorScene` 的读规则过一遍：服务端传来的数据也按不可信处理，读不懂的元素跳过。

#### 7.9.3 渲染服务

- 单独部署：一个常驻的 Chromium，预热 N 个页面（环境光只算一次），请求排队；单次渲染限时，超时就关掉这个页面重开；每个页面渲染若干次后换新；队列满了直接拒绝。
- 渲染服务和主服务之间用共享密钥鉴权，网络上只允许主服务访问它。
- **安全**：输入只有经过校验的场景数据，没有代码。渲染页的请求全部拦截，只放行自己的静态文件；贴图和背景上线后，再放行渲染服务自己的素材代理。
  素材代理按对象键规则取本项目对象存储里的素材（同 `view_node_media` 的防 SSRF 规则，反解不出对象键就拒绝，不发请求）。渲染服务不持有对象存储的写凭证。
- 控制浏览器的库只装在渲染服务里，不进主服务的运行时依赖。
- 本地开发可以直接用本机的 Chrome 起渲染服务，在 `.env` 里配 `DIRECTOR_RENDER_URL`。

#### 7.9.4 两种工作：看图与出片

| | `render_view`（看） | 运镜出片（`video` 端口） |
|---|---|---|
| 调用方式 | 同步请求，返回 PNG | 异步任务，可查进度、可取消 |
| 耗时 | 秒级 | 分钟级（帧数 × 每帧耗时，待 P0 实测） |
| 资源 | 低延迟的小池 | 单独排队，优先级低，每个任务限时；不能堵住看图 |
| 产出 | 图片交给模型 | 视频回传主服务，由主服务存对象存储，再写到节点的输出端口 |

- 出片是**离线逐帧渲染**：按 `t = i / fps` 步进，每帧求值后截帧，原始像素交给 ffmpeg 编码。不是实时录屏，也不依赖页面里的视频编码器。
- 人在视口里预览运镜是纯前端的事：用同一个渲染库从机位播放，不经过渲染服务。
- `image` 端口的截图就是一次服务端单帧渲染。
