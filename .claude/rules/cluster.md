**单副本 / 多副本 (`apps/server/cluster/`) — one image, two modes, picked by env.** Full write-up in `docs/14-clustering.md`. `CLUSTER_MODE` (`single` | `redis`) resolves exactly like `dbProvider`: explicit variable wins, else infer from whether `REDIS_URL` is set, else the zero-dependency default. **Database and Redis are configured independently** — neither infers the other; `assertClusterConfig()` rejects `redis` without a `REDIS_URL` everywhere (contradictory config), but `redis` + SQLite only *warns* in dev, because SQLite + Redis in one process is a legitimate way to exercise the Redis path locally. Production refuses it.
- The state that used to be module-level `Map`s — audit `seq`, quota marks, awareness clientID ownership, session-refresh mutex — is now three abstract classes in `cluster/shared.ts`: `SharedMap<V>` (`get`/`set`/`claim`/`entries`, TTL), `SharedCounter` (`next(key, seed)`), `SharedLock` (`run(key, task, {fallback})`). Two implementations, `memory.ts` (literally the old `Map`s) and `redis.ts` (`SET NX` / `INCR` / lock+Lua-release), run the same contract test suite (`apps/server/test/cluster/shared.test.ts` — memory always, Redis when `TEST_REDIS_URL` is set). The backend also answers `health()` (surfaced as `clusterHealth()`), which is **synchronous and sends no network request** — it reads ioredis's own `status` field, because a health check must not hang when the thing it checks is slow; only `ready` counts as usable, since during `connecting`/`reconnecting` commands silently pile into the offline queue.
- **Every method is async even in the memory implementation** — otherwise wiring in Redis later would have meant changing every call site's signature. And **the factories return lazy proxies**: modules declare their tables at module top level (the way they used to write `new Map()`), but picking an implementation needs `await import('ioredis')`, which happens later in `initCluster()`. The proxy resolves against the current backend on first use, so swapping backends just bumps a generation counter.
- **`redis.ts` is dynamically imported**, like the two database drivers in `db/orm.ts` — a single-replica process never loads ioredis. Like the drivers, both packages stay in the built artifact: the image supports either mode, and nothing about the database is baked in at build time either.
- Multi-replica collab is `@hocuspocus/extension-redis` (pub/sub for updates + awareness, redlock around `onStoreDocument` so only one instance actually writes, `afterLoadDocument` waits for a peer's in-memory state). **socketId gets an `instanceId:` prefix** — Hocuspocus's socketId is only unique within a process, and awareness ownership uses it to tell "is this clientID yours", so a collision would drop the rightful owner's updates as impersonation. No sticky session needed anywhere.
- **The same update fires `onChange` on *every* instance holding the room.** Nothing writes per-update rows today, but anything that starts to (webhooks, notifications, metrics) must filter on `transactionOrigin` and skip `source === 'redis'` — otherwise the side effect fires a multiple of the replica count (measured back when the audit table existed: two instances, 11 edits, 22 rows), and the forwarded copy carries no author `context` anyway. Unknown origin shapes should count as "act" — better one too many than losing the author's.
- **Quota is deliberately eventually-consistent**: `quotaLocked()` is called *synchronously* on every message, so it reads a local `Map`; the verdict is pushed to the shared layer fire-and-forget and pulled back on the byte-remeasure tick (1–5s). That matches what the quota already was — after-the-fact accounting, effective on the *next* message — not a synchronous gate.
- Local: bring up Redis/PostgreSQL yourself (commands are in `.env.example`; the scripts deliberately don't), then `pnpm dev` (single) or `pnpm dev:cluster` (`apps/server/scripts/dev-cluster.mjs` spawns one `tsx watch` per port from `DEV_CLUSTER_PORTS`, overriding only `PORT` and `INSTANCE_ID` — **it contains no configuration**, everything else comes from `.env`). k8s: `k8s/deployment.yaml` (single, PVC, `Recreate`) or `k8s/variants/deployment.cluster.yaml` (`replicas: 3`, `RollingUpdate`, no PVC) — the two are one Deployment identity in two shapes, and **the variant deliberately lives outside `k8s/`**: ArgoCD syncs that directory non-recursively, so two manifests for `dev/shadecn-learning` sitting in it is a `RepeatedResourceWarning` with no guarantee which one wins. Switching is a git operation (copy the variant over `k8s/deployment.yaml` and commit) — applying it by hand gets reverted by `selfHeal` within seconds.
