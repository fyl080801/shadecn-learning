# App execution — `packages/mod-apps` (REQ-APPS, `docs/29-apps.md`)

- **A new upstream service = one file in `src/drivers/` + one line in `drivers/index.ts`'s `DRIVERS`.** A new app = an item in `modules.apps.apps`, no code. **A driver's `operations` keys are the categories** (the item's `type` picks one): never add a `category` elsewhere or a per-driver branch to reach one (ComfyUI generates one operation per category from the same factory). Never add a driver-specific branch to `catalog.ts`, `params.ts`, `routes.ts` or `contract.ts` — if a driver needs something generic, add it to `driver.ts` (`Fields`) / `http.ts` / `params.ts` for everyone.
- **Drivers don't validate params, apply defaults, time out, poll or normalize errors** — `catalog.ts` does (`resolveParams` → `AbortSignal.any([caller, timeout])` → `submit` → `pollUntilDone` → `normalizeError`). A driver declares its `params` schema and gets validated `values`; every upstream request goes through `http.ts` (`requestJson` / `requestBytes` / `requestOk`) with `ctx.signal` and `ctx.fetch` — never a bare `fetch`, never its own timer or loop (the app's `timeoutMs` is already in the signal).
- **Execution is `submit` / `poll` / `cancel` (`docs/29` §3.2)**: a sync upstream returns `{ done: true, output }` from `submit`; a task-type upstream returns a **resume handle** `{ upstreamId, state? }` and implements `poll` (check **once**, no loop, no sleep — interval is `pollIntervalMs`, the loop is the executor's) and optionally `cancel` (best effort). The handle must be JSON-serializable and carry everything `poll` needs after a restart (e.g. Ark 3D's `fileFormat` in `state`) — never something only the closure of that `submit` call knows, and never a secret. The time limit runs from `ExecuteOptions.startedAt` (resume passes the task's start; an expired one fails `timeout` without a request). Cross-param rules the schema can't express (Ark video's first/last frame) are the driver's, thrown as `AppError('invalid_params')` before the first request.
- **Config fields are read only through `Fields`**; the catalog calls `done()` after `parseProvider` / `prepare`, so an unread field is a boot error — read every field you accept, or it reads as a typo. Shape errors throw (no listening port); "configured right but unusable now" (`$ENV` unset, model unresolvable) is `fields.unavailable(reason)` and the driver still returns its category + params — never throw for it.
- **Secrets only as `"$ENV"`** (`Fields.secret`); a literal is a boot error and the message never echoes the value. Env goes through `DriverEnv.envVar` (= `runtime.envVar`) — drivers never read `process.env`.
- **The server never fetches a caller-supplied URL** (SSRF): Ark gets image URLs passed through to Ark; ComfyUI and the LLM driver accept image params only as `data:` URLs. Don't add a "download the URL and upload it" fallback. The canvas entry (`flow-assets.ts`) turns a URL into bytes **only** via `storage.assets.read` (URL → own-bucket key by string match, then `FlowAsset` ownership for *this* flow — no request to the URL); anything else stays a URL. The one outbound fetch of a URL is a **provider-returned output** (admin-configured upstream, https only, size + time capped) in `persistFlowOutputs`.
- **Drivers know no concrete model.** The base param schema is the union across a family's generations; per-model narrowing is written in the `apps` item's `params` (a `ParamPatch` on the base table), applied in `catalog.ts`. Never put a model id, prefix or `if (model …)` in a driver — add an item to `sample/server.config.example.yaml` (pinned by `test/example.test.ts`). `model` is reserved and is **not a param**: the item fixes it and the executor passes it to `submit`; a driver schema or an item's `params` containing it is a boot error. Model availability is `PreparedApp.checkModel`, which marks only that app `unavailable` (not a boot error).
- **One item = one provider + one model; the app id is derived** (`<provider>:<model>`, or `<provider>:<id>` when the operation doesn't take a model) and is opaque outside `catalog.ts` — never parse it, and always encode it in a URL (model ids may contain `:` or `/`). `modules.apps.providers` / `.apps` are `setting('json')` leaves: invalid JSON is a boot error whose message never echoes the text (no `cause` either, `JSON.parse` quotes it). Configuration has no file of its own and no reuse mechanism: each item spells out its `params`.
- **Wire shapes live in `@shadecn/shared/apps`** (`AppInfo`, `ParamSpec`, `AppResultView`, `nodeAppParams`); `mod-apps/contract.ts` re-exports them. The node → params mapping keys off the param schema (`prompt`, first `images`/`image`), never off the driver.
- **The LLM drivers reuse the agent's model path** (`@shadecn/agent/llm-providers` `resolveProviderModel` / `@shadecn/agent/model` `resolveAgentModel` + `@shadecn/agent/model-stream` `streamUpstream`): don't write another OpenAI-compatible client. Connection info belongs in `llm.providers` (`type: llm` references it; `DriverEnv.llmProviders`). **Each model of a provider with models becomes a text app by a pure pre-parse step** (`llm-apps.ts` `withLlmProviderApps`, called from `catalogFromConfig`): raw data in, raw data out, so `buildCatalog` / `checkModel` run unchanged and know nothing about it; a colliding provider id is a boot error, a colliding app hits the generic duplicate check. A model's `images` param is narrowed by the generated `params: { images: null }`, never by a branch in the catalog. Images must really reach pi as image input: an `options.imageInput: true` passes through `resolveProviderModel`, because pi silently swaps images for a placeholder on a text-only model.
- **The global server test env has no apps** (`SERVER_CONFIG=''`, no `MODULES_APPS_*` JSON → module off). Enabling it for every test file shifts boot timing and makes `importFreshApp()` + `signIn()` collide on SQLite's write lock with mod-auth's startup sweep (5 s busy timeout). Route tests call `stubAppsConfig()` (`test/helpers/apps-config.ts`) and rebuild the app **after every DB write** (sign-in, projects, `FlowAsset` rows — `test/routes/apps.test.ts`, `flow-apps.test.ts`); swap storage on the *fresh* graph (`await import('@shadecn/mod-storage')` after `importFreshApp()`).
- **Canvas generation is a task (`docs/29` §3.10): the web role only accepts, the agent role executes and writes back.** `POST …/execute` validates (`service.validate`), creates the `app_task` row, `bus.dispatch(APPS_RUN_TASK)` and returns 202 — no fast path, even in one all-roles process (same rule as agent runs). `task-runner.ts` (agent role, `dependsOn collab` there) claims the row, holds a direct connection to the live room for the whole task (broadcast `apps:tasks` must come from the replica holding the room), and writes the result **server-side** with `flow-ops` `recordGeneration` (`attachAsset` + the `gen.<taskId>` history entry, one transaction — never a bare `attachAsset`, or the result is missing from the history) or, for a text app, `appendGeneratedText` (**appends** to non-empty `data.text`: a server write is in nobody's undo stack, so overwriting what someone typed during generation is unrecoverable; thinking never enters the node) + `writeNodeFields(…, 'runtime', …)` under `appsOrigin(taskId)` (in nobody's `trackedOrigins`). **The task runs as its initiator** (`task-authority.ts`, the agent Grant's semantics without a table — `docs/29` §3.10): `issue` at claim (no access → task failed, no room opened, no upstream call), `authorize('flow:read')` before reading reference assets, `authorize('flow:write')` before saving outputs and before every node write, and once per lease renewal; effective = member now ∩ same project / personal owner as the snapshot, verdict cached ≤ 3s; `onAccessRevoked` → `reconcileLive`. A revoked verdict calls `stop` → abort reason `revoked` → cancel upstream, task failed, **no node write**. It never looks at the session. Never replace it with a one-off membership check. Writes are skipped unless that authorization passes, the room isn't quota-locked, the node exists and its `runtime.taskId` is this task. **The frontend never writes `runtime` or a result**: `app-run` only submits (+ `useFlowAppTasks().upsert`); a rejected submit is a toast, not an `error` state. `processing` means "an executor is running it"; queued lives only in the task list (`taskOn(nodeId)` — the node overlay, `isGenerating`). Canceling a queued task makes the web route `dispatch(APPS_PUSH_TASKS)` so one agent replica re-pushes the list (nobody else would). Never `setData({ src })`. It reads `data.appId` through `resolveNodeApp` and never writes a default back.
- **`app_task` is the lifecycle's source of truth; every transition is a conditional `nativeUpdate`** (`tasks.ts`): claim = active ∧ (no lease ∨ lease expired); every executor write = `leaseOwner = me` ∧ active (so a cancel or a takeover makes the old holder's writes no-ops — check the returned count before writing the node); cancel = active → `canceled`, regardless of lease. Never read-then-write a status. The executor renews every lease/3 and aborts on a failed renewal (`canceled` → cancel upstream + node `idle`; otherwise `lost` → write nothing). Shutdown releases the lease (`shutdown` reason) instead of failing the task. The sweeper (every agent replica) takes over expired-lease tasks: with a handle → `resumeApp` (never resubmit — double billing); `running` without a handle → failed "执行中断". Progress goes to the row + the push, **never into the Y.Doc** (high-frequency; the doc only gets state transitions).
- **Frontend task state has one home: `composables/flow/useFlowAppTasks.ts`** (provided in `FlowEditor.vue`; `flowAppTasksFor(flowId)` for the node runner, which has no inject). One `GET` on open + per reconnect, then only `apps:tasks` pushes (full list, replace; an in-flight `GET` never overwrites a newer push) — no polling. A task whose node `runtime.taskId` points at it but isn't `processing` is hidden (the executor writes the node before it pushes). The node's processing overlay (`StatusProcessing.vue`) and the top-right **generation tasks button** (`components/flow/apps/FlowAppTasksButton.vue`, its own Popover — never merged back into the agent chat button, whose count is agent runs only) read it; "is this node generating" = `runtime.status === 'processing'` **or** a queued task in this list (`taskOn`).
- **`size` validation is shared** (`@shadecn/shared/apps` `checkParamValue`, re-used as `params.ts`'s `checkOne`): the popover (`SizePicker.vue`) and the server must reject the same values — never add a size rule in only one of them. Tiers / presets / pixel ranges are per-model config (the item's `params`), never in the driver or the component. Node overrides live as `data["appParam.<name>"]`, one key per param, and are filtered by the chosen app's schema at run time (`nodeAppParams`) rather than cleared when the app changes.

## `@learning/apps` (`packages/apps`, the Nest service, `docs/30` §8)

The invariants above hold, with `modules.apps` read as config.yaml's `apps` section. What differs, and what the obvious change gets wrong:

- **A separate implementation, nothing shared with `mod-apps`.** A driver fix goes into both.
- **There are no roles and no dispatch: the route calls `TaskRunner.runTask` directly.** `AppsModule` is only in the platform, which both accepts and executes. Don't add `Bus.dispatch` for this. `APPS_CANCEL_TASK` stays on the bus: a task may be running on another platform process. Anything that must reach those processes goes through the bus or the row; the sweeper is what catches a task nobody claimed.
- **Results go into the room, never straight into the database**, through a direct connection held for the whole task. The platform's `CollabModule` has no upgrade listener; in the split shape the Redis extension relays writes and `broadcastStateless` to the replicas holding the room, and `afterLoadDocument` waits for a peer's unsaved state. That is why the platform must run `cluster: redis` there: with `single` the room is an island and users see the result only after a reload.
- **`TaskRunner` stops in `onModuleDestroy`, not `beforeApplicationShutdown`**: `CollabServer` closes rooms and the Redis extension in the latter, and disconnecting a task's direct connection (store, unload) needs them open. Nest finishes every module's `onModuleDestroy` before the next phase, whatever the module order.
- **`active_key` decides "one task per node", by its unique constraint.** Never check first and insert after: two requests both see none and both insert. Every path to a terminal state (`finish`, `cancel`) must clear it, or the node can never submit again.
- **The model path is `@learning/llm`, a copy of the agent's model path, not a new client.** The rule above against writing another OpenAI-compatible client stands. `llm.providers` has exactly one parser (`@learning/llm/llm-config`); never parse it again in `packages/apps`.
- **`CollabServer.quotaLocked` is the only quota check a direct connection gets**: it bypasses the write gate and `beforeHandleMessage`, so a writer that skips it can push a locked room further over.
